# ReLevel — задачи разработки

## Как пользоваться

- Требования находятся в [SPEC](docs/SPEC.md); правила разработки — в [AGENTS](AGENTS.md).
- Здесь фиксируются оставшаяся работа, вопросы и фактически выполненные проверки.
- Статусы: «К выполнению», «В работе», «Проверить в Revit», «Готово», «Нужно решение».
- При общей команде продолжить разработку выбирать первую незаблокированную задачу. Задачи со статусом «Нужно решение» не реализовывать без согласования поведения.
- Сборка подтверждает компиляцию. Результат ручной проверки записывать с версией Revit и проверенными случаями.

## R14. Сохранять размещение семейств при переносе стены

**Статус: Проверить в Revit.** Требования: SPEC → «Случай 2». Пользователь сообщил: при смене уровня стены стена остаётся на месте, а размещённое на ней семейство смещается. Требуется сохранять положение семейства; его уровень менять только при отдельном выборе для переноса. ID стены/семейства и версия Revit для этого прогона не указаны.

- Добавлен WallHostedPlacement: поиск непосредственных FamilyInstance по свойству Host среди экземпляров текущего документа и сохранение ID/LocationPoint.Point до записи стены. Вложенные экземпляры отдельно не обрабатываются. Семейство без LocationPoint даёт ошибку с ID до записи; для других способов размещения алгоритм пока не реализован.
- TwoLevelOperation после записи всех пар стены вызывает Regenerate и восстанавливает точки в той же Transaction. Параметры уровня семейства не записываются; восстановление не зависит от его выбора и принадлежности Кейсу 3. Колонны и стены без хостовых семейств обходятся без дополнительного Regenerate. Ошибка восстановления откатывает операцию стены; критическая ошибка регенерации передаётся существующему обработчику без чтения повреждённого документа.
- Пакет по-прежнему переносит только выбранные ID последовательно. Отдельно выбранное семейство выполняет свой кейс; восстановление точки стеной не записывает его уровень ни до, ни после этой операции. Проверки результата и геометрические сравнения не добавлены. Обновлены SPEC, README и переводы; Legacy и ELEMENTS.md не менялись.
- Проверки: `dotnet build ReLevel.sln -c Release` с API Revit 2025 — 0 ошибок, 0 предупреждений; основная DLL обновлена в `bin/2025+/ReLevel/ReLevel.Revit.dll`. Проверены ключи и подстановки новых сообщений, `git diff --check`, по коду — отсутствие записи параметров уровня в WallHostedPlacement. Unit-тесты не добавлялись по AGENTS; в Revit операция агентом не запускалась.
- Следующий шаг на копии модели: выбрать только стену — проверить сохранность точки и прежнего Schedule Level семейства; выбрать стену и семейство — проверить перенос обоих уровней при обоих порядках обработки; проверить несколько семейств с разными уровнями, стену без семейств, отказ восстановления и Undo стены вместе с точками. | FAMILY_LEVEL_PARAM только для чтения | После R06 не попадает в таблицу; повторная проверка перед записью остаётся |
| Ошибка записи, восстановления точки или фиксации, если воспроизводится на модели | Изменения этого экземпляра откатываются; успешный перенос не засчитывается |
| Несколько отмеченных строк, поиск и фильтр | Обрабатываются только отмеченные видимые строки; результаты доступны по ID |
| Русский/английский язык, смена уровня и повторный запуск команды | Подписи и причины отображаются корректно, данные обновляются |
| Undo после одного и нескольких переносов | Один Undo отменяет один успешный перенос экземпляра |

**Результаты запуска Revit: не получены.** Пользователь планирует ручную проверку; сборка не заменяет её.

## Открытые вопросы по видам


### D1. Что сохранять в секущем диапазоне и подложке?

**Статус: Нужно решение.** Не блокирует независимые задачи.

- SPEC сохраняет выбранное ранее правило: копировать уровни диапазона и подложки без пересчёта.
- В `ViewSettingsSnapshot.Apply` исходные ID уровней и смещения действительно записываются в новый вид.
- Это может оставить ссылку на исходный уровень. Относительные значения диапазона также могут дать другое видимое сечение на новом уровне.
- Нужно выбрать: сохранить параметры буквально либо при ссылке на исходный уровень заменить её и сохранить абсолютные высоты там, где это требуется.
- До согласования не менять алгоритм. После решения обновить SPEC и поставить точную задачу с примерами до/после.

### D2. Допускать ли побочные изменения исходных объектов при пересоздании вида?

**Статус: Нужно решение.** Не блокирует независимые задачи; решить до приёмки на рабочих проектах.

- SPEC сохраняет прежнюю политику: журналировать изменения/удаления существующих объектов и оставлять результат для проверки через Undo.
- В `ViewOperationLog.Run` эта политика реализована. Сообщение о создании нового вида не гарантирует неизменность всей исходной модели.
- Предлагаемое усиление: неожиданные изменения исходных модельных объектов или их удаление откатывают затронутый этап; допустимые служебные обновления обрабатываются отдельно.
- Это изменение поведения, а не редактура текста. Сначала согласовать границу отката и допустимые изменения, затем обновлять SPEC и код.

### T09. Проверки содержимого пересозданных видов

**Требования:** SPEC → «Аннотации, детализация и графика», «Ошибки и журнал».

- Отличать факт создания вида от полноты и проверенности результата. Непроверенная аннотация не должна выглядеть как полностью проверенная.
- Проверка: текст с выноской; марка с корректной и потерянной ссылкой; обычный размер; высотная отметка без BoundingBox; неоднозначные копии; ноль успешных вставок. ID потерь и непроверенных объектов доступны в журнале.

**Результат реализации, 2026-09-29:**

- `AnnotationSnapshot` снимается до копирования. Проверяются класс/тип, текст и выноски TextNote; текст, положение и доступные ссылки/выноски IndependentTag и пространственных марок; значения, подстановки и ссылки размеров; доступные числовые параметры высотных отметок без требования BoundingBox; линии детализации и границы областей заливки.
- Положение сравнивается в плоскости вида. Ссылки на модельные объекты сопоставляются по устойчивому представлению; ссылки на объекты самого вида, неподдержанные типы, неоднозначные копии и недоступные свойства получают явное замечание. Форматирование фрагментов текста и часть выносок/положений сегментов размеров остаются ручной проверкой.
- В журнале различаются потери, ошибки сравнения и непроверенные объекты. Сводка сообщает число копий без замечаний автоматической проверки, не обещая полной проверки вида. Повторные проверки не дублируют одинаковое замечание.
- Проверены код, локализация и компиляция. Копирование и соответствие реальных аннотаций не проверены в Revit; политика частичного результата не изменена.
