## Как пользоваться

- Требования находятся в [SPEC](docs/SPEC.md); правила работы агента — в [AGENTS](AGENTS.md).
- Здесь фиксируются расхождения с кодом, оставшаяся работа и результаты проверок. Реализованные требования из SPEC не удаляются.
- Статусы: «К выполнению» → «В работе» → «Проверить в Revit» → «Готово». Для вопросов используется «Нужно решение».
- Начинать с первой доступной задачи в порядке ниже. Уже существующие функции сначала проверять, а не переписывать.
- После работы добавить к задаче короткий результат: коммит, выполненные проверки, версия Revit и оставшиеся ограничения. Не вести журнал каждого изменения строки кода.

## Вопросы, которые нельзя решать за пользователя

### D1. Что сохранять в секущем диапазоне и подложке?

**Статус: Нужно решение.** Не блокирует задачи поиска и переноса элементов.

- SPEC сохраняет выбранное ранее правило: копировать уровни диапазона и подложки без пересчёта.
- В `ViewSettingsSnapshot.Apply` исходные ID уровней и смещения действительно записываются в новый вид.
- Это может оставить ссылку на исходный уровень. Относительные значения диапазона также могут дать другое видимое сечение на новом уровне.
- Нужно выбрать: сохранить параметры буквально либо при ссылке на исходный уровень заменить её и сохранить абсолютные высоты там, где это требуется.
- До согласования не менять алгоритм. После решения обновить SPEC и поставить точную задачу с примерами до/после.

### D2. Допускать ли побочные изменения исходных объектов при пересоздании вида?

**Статус: Нужно решение.** Не блокирует независимые задачи; решить до приёмки на рабочих проектах.

- SPEC сохраняет прежнюю политику: журналировать изменения/удаления существующих объектов и оставлять результат для проверки через Undo.
- В `ViewOperationLog.Run` эта политика реализована. Сообщение о создании нового вида не гарантирует неизменность всей исходной модели.
- Предлагаемое усиление: неожиданные изменения исходных модельных объектов или их удаление откатывают затронутый этап; допустимые служебные обновления обрабатываются отдельно.
- Это изменение поведения, а не редактура текста. Сначала согласовать границу отката и допустимые изменения, затем обновлять SPEC и код.

### T02. Расширить поиск связей с уровнем

**Статус: Проверить в Revit.**

**Требования:** SPEC → «Поиск связей с уровнем».

- Код: `Transfer/LevelRelations.cs`, `LevelRelationFinder`; `UI/TransferWindow.cs`, `Refresh`; `UI/LevelRelationText.cs`.
- Добавить обнаружение верхних привязок и известных косвенных связей. Возвращать не только факт совпадения, но и основание: низ, верх, опорный уровень, хост или плоскость.
- Поиск не должен отсеивать элемент из-за невозможности его переноса. Неизвестный механизм и неустановленная связь — разные результаты.
- Проверка: стена только с верхом на источнике, колонна, обычное семейство, семейство на грани и MEP. Одна строка на ID, понятная причина связи/пропуска.

**Результат реализации, 2026-09-28:**

- Изменения в рабочем дереве поверх `a85370b2f72765305e739b3643e87a45bceea259`; отдельный коммит не создавался. Согласованные требования и Legacy не изменялись.
- Поиск отделён от анализа переноса. К прежним параметрам добавлены верх стены (`WALL_HEIGHT_TYPE`), верх семейства (`FAMILY_TOP_LEVEL_PARAM`), конечный опорный уровень MEP (`RBS_END_LEVEL_PARAM`), верх лестницы и крыши. Читаются также доступные параметры только для чтения; отрицательные служебные ID и ссылки не на Level не считаются уровнями.
- Для семейств обходятся `Host` и локальная ссылка `HostFace`; для рабочей плоскости — доступный объект через `SKETCH_PLANE_PARAM` и `CurveElement.SketchPlane`. По известной цепочке обход продолжается до уровня или элемента с явными параметрами уровня. Повторное посещение ID исключено; общие хосты читаются один раз за обновление.
- В результате и строке сохранены ID уровня, вид привязки, параметр, его владелец и путь косвенной связи. Статус показывает нижнюю/верхнюю/опорную привязку либо хост/грань/плоскость с ID вместе с прежней причиной ограничения. В режиме выделения показаны все найденные уровни; в режиме уровня — основания совпадения с источником. Результат операции не скрывает основание связи.
- В рамках T02 перенос не расширялся: верхняя привязка стены, двухуровневые семейства, размещение на хосте/плоскости и MEP остались под прежними ограничениями. Дальнейшие изменения плана переноса описаны в T03.

**Оставшиеся ограничения:**

- Это поиск известных API-связей, а не всех возможных зависимостей. Другие механизмы хостов, произвольные параметры и ограничения модели автоматически не интерпретируются.
- Если плоскость/хост не предоставляет явной связи с уровнем, результат остаётся неопределённым; имя, отметка плоскости и высота элемента не используются. В режиме уровня элемент без подтверждённого совпадения не включается; причину можно увидеть в режиме исходного выделения.
- Хост из связанной модели обозначается с ID, но уровни связи не сопоставляются с уровнями текущего документа. Самостоятельная локальная привязка семейства, если она есть, учитывается. Содержимое связи не обходится и не изменяется.

**Фактически проверено:**

- По коду: отбор до анализа переноса, одна строка на ID, обход с защитой от повторов, сохранение основания после операций, отсутствие геометрического поиска и изменений модели в компоненте поиска. Стратегии и сервис переноса не изменены; из анализатора удалён только прежний поиск `IsOnLevel`.

### T03. Расширить план переноса и проверки зависимостей

**Статус: Проверить в Revit.**

**Требования:** SPEC → «Перенос элементов / Общие правила».

- Код: `ITransferStrategy`, `TransferPlan`, `TransferService.Execute/TransferOne`, вызов переноса из `TransferWindow`.
- Передавать контекст операции явно и поддержать несколько изменяемых привязок вместо одной пары параметров и передачи только цели.
- Разделить определение связей и выбор способа изменения. Не заменять нижний уровень только потому, что элемент найден по верхнему.
- Предусмотреть проверяемый состав зависимостей вместо безусловного отката изменения любого другого объекта; простое снятие защиты `unexpectedChanges` недопустимо.
- Сохранить работающий путь для простых элементов. Для связанной операции откат должен возвращать все затронутые элементы.
- Проверка: менять только нужную привязку; не трогать другую; неоднозначное выделение пропускать; побочные изменения откатывать.
- Текущие допуски в `GeometrySnapshot`: координаты `1e-5 ft`, поворот `1e-9 rad`, объёмы/площади `max(1, |исходное|) × 1e-9`. Не ослаблять их без конкретного воспроизводимого случая.
- Если равная геометрия отвергается из-за порядка тесселяции, разобрать пример отдельно. Не переписывать сравнение заранее без доказанной необходимости.

**Результат реализации, 2026-09-28:**

- Добавлены `TransferContext`, список `TransferBinding` и явно объявляемые `TransferDependency`. Интерфейс, предварительный анализ и сервис передают один и тот же режим, исходный и целевой уровни. Перед записью план пересчитывается; изменение состава привязок/зависимостей прекращает попытку.
- Меняются только пары, чей исходный уровень совпадает с источником; остальные пары и неактивный верх стены проверяются на неизменность. Каждая изменяемая пара имеет отдельный расчёт смещения. Все записи выполняются до первой регенерации, затем проверяются после регенерации и после Commit.
- Режим выделения с несколькими найденными уровнями пропускается с объяснением. Косвенная связь без самостоятельной привязки не превращается в запись параметра. Ошибка чтения связи блокирует перенос, сохраняя диагностический ID.
- `TransferSnapshot` проверяет геометрию с прежними допусками, уровни, хост/грань, состав вложенных компонентов, закрепление, группу/сборку/вариант и геометрические соединения. Для объявленной зависимости дополнительно сравниваются все доступные параметры. Добавление/удаление любого объекта и изменение объекта вне разрешённого состава откатывают попытку. Разрешённое механизмом обновление зависимости тоже требует успешной проверки снимка.

## Матрица ручной проверки T01–T13

Проверять на копиях моделей. Для каждого случая записать точную версию Revit, ID объектов, источник/цель, результат и сообщения. Сначала отдельные элементы, затем отмеченный набор. Для успешных операций проверить перенос вверх и вниз, повторный запуск и один Undo всего пакета. Перед/после сравнить реальные координаты и связи, а не только видимую картинку.

| Случай | Ожидаемый результат |
| --- | --- |
| Стена связана с источником только верхом | Есть в поиске с основанием «верх»; меняются верхняя привязка и её смещение; низ и геометрия прежние |
| Стена/колонна: источник снизу, сверху, с обеих сторон | Меняются только соответствующие привязки; положение, высота и сечение сохраняются; другой конец неизменен |
| Стена/колонна с двумя уровнями в режиме выделения | Понятный пропуск неоднозначного источника; в режиме уровня доступен определённый источник |
| Обычное одноуровневое семейство разных категорий | Уровень заменён, абсолютные координаты и ориентация прежние; повторный перенос на ту же цель не меняет модель |
| Стена с дверью, окном, проёмом, примыкающей стеной | Вставки, контуры, хосты и соединения сохранены; разрешённые производные уровни вставок проверены; непредусмотренное изменение откатывается |
| Перекрытие/потолок с отверстием и размещённым семейством | Геометрия хоста, отверстие и размещённый элемент сохраняются; нет новых/удалённых объектов |
| Семейство на грани/плоскости/хосте, в том числе в RVT-связи | Самостоятельная привязка меняется только если доступна; хост/грань не меняются. Иначе пропуск с причиной; локальный уровень не угадывается по связанному |
| Семейство со вложенными компонентами | Состав, размещение и известные производные привязки проверены; вложенный экземпляр самостоятельно пропускается |
| Труба/воздуховод/лоток/короб: горизонтальный и наклонный | Опорный уровень заменён, оба конца и уклон прежние; свободные концы остаются свободными |
| Трасса с фитингом, арматурой, оборудованием и непереносимым соседом | Коннекторы, сечения, ориентация, связи и состав систем/цепей прежние; уровень соседа не переписывается |
| MEP без системы; прибор в электрической цепи | Отсутствующая система не становится причиной отказа сама по себе; существующая цепь и её оборудование сохраняются |
| ReadOnly/неизвестная привязка; закрепление/группа/сборка/вариант | Пропуск с ID и причиной без изменения модели; доступность поиска сохраняется |
| Намеренно созданное ограничение/предупреждение, побочное изменение или разрыв связи | Попытка откатывается вместе с зависимостями; успех не засчитывается. Критический сбой отменяет пакет и прекращает чтение модели |
| Текст, марка модели/связи/помещения/пространства/площади, размер, высотная отметка | Сравнены применимые текст/значения/положение/ссылки; потери, несовпадения и непроверенные свойства имеют исходные ID в журнале |
| Неоднозначная копия, неподдержанная аннотация, ноль успешных вставок | Неполный результат явно указан; факт создания вида не показан как полная проверка содержимого |
