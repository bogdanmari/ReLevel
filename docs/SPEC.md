# Спецификация ReLevel

## Назначение

ReLevel — плагин Autodesk Revit 2025 на C#/.NET 8. Изменение уровня должно сохранять положение и геометрию элемента с допустимой численной погрешностью: `ModelPositionBefore ≈ ModelPositionAfter`.

Для поддержанных механизмов: `новое смещение = старое смещение + отметка исходного уровня − отметка целевого уровня`. Пример: уровень 0 мм и смещение +1200 мм → уровень +3000 мм и смещение −1800 мм. Используется `Level.ProjectElevation`, вычисления API выполняются во внутренних футах.

## Текущая итерация

Цель — простой интерфейс и чистая структура без переписывания существующих алгоритмов переноса. Полный охват связей с уровнем, перенос всех категорий и полное пересоздание видов не заявляются реализованными.

### Основное окно

- Начальный размер — 920 × 607,2 единицы WPF; открытие по центру экрана.
- Одна верхняя строка: ComboBox «Уровень» и CheckBox «Работать с выбранными элементами».
- Исходное выделение фиксируется до запуска окна; без выделения CheckBox недоступен.
- Режим выделения очищает и блокирует ComboBox; при выключении он доступен, уровень нужно выбрать снова.
- Смена режима/уровня обновляет таблицы и сбрасывает отметки строк.
- Две вкладки: «Элементы» и «Виды». Вторая блокируется в режиме выделения; виды по видимости выбранных элементов не ищутся.
- Состояние существует только в памяти окна. Базы данных, файлы истории и параметры проекта не используются.

### Элементы

В режиме уровня показываются результаты существующего поиска `TransferAnalyzer.IsOnLevel`: элементы модели, не специфичные для вида, по `LevelId` и известным параметрам базового/опорного уровня. Это не полный поиск связей. В режиме выделения показываются существующие элементы исходного выделения.

Колонки: отметка, ID, категория, `Element.Name`, статус/причина. В режиме выделения добавляется «Уровень», определяемый тем же ограниченным поиском; при нескольких найденных связях уровни перечисляются, при отсутствии — «Не определён».

Кнопки под таблицей:

- «Выделить элементы» — устанавливает выделение Revit по отметкам, сохраняя исходный список выделения.
- «Удалить элементы» — проверка, подтверждение с количеством объектов и зависимостями, транзакционное удаление. Удаление уровней запрещено. Для видов используется вкладка «Виды».
- «Перенести элементы» — диалог целевого уровня и существующий анализ/перенос. В режиме уровня источник исключён из целей; в режиме выделения уже находящиеся на цели элементы пропускаются.

После операций таблицы обновляются, отметки сбрасываются, результат показывается по ID. При переносе различаются перенесённые, пропущенные и ошибки. Перенесённый элемент может исчезнуть из таблицы исходного уровня, поэтому отчёт показывается отдельно.

### Виды

Правила и алгоритмы переноса или пересоздания видов описываются в [Views.md](../Views.md). Этот документ служит основой для реализации в рамках отдельной задачи; описание будущего поведения не означает, что оно уже реализовано.

Показываются нешаблонные виды с `View.GenLevel`, соответствующим выбранному уровню. Колонки: отметка, ID, имя и тип.

- «Открыть виды» — последовательное открытие отмеченных видов; ошибки по ID.
- «Удалить виды» — подтверждение с количеством объектов, содержимого и зависимостей. Зависимые виды и виды с зависимыми видами отклоняются. Уровень не удаляется.
- «Пересоздать виды» — явно недоступно с объяснением: настройки, аннотации и связи пока не переносятся. Частичная копия не создаётся.

При реализации пересоздания в отдельной итерации диалог должен содержать целевой уровень и префикс имён; источник и цель должны различаться, исходные виды должны сохраняться. Это будущее требование, не действующая функция.

### Общие правила

Над каждой таблицей расположена визуальная строка поиска: кнопка «Фильтр» слева, поле ввода, справа счётчик вхождений и стрелки вверх/вниз. Пока реализован только внешний вид: ввод не меняет таблицу, счётчик показывает «— вхождений», фильтр и переходы недоступны. В дальнейшем фильтр должен оставлять только совпадающие строки.

Кнопки под таблицами выровнены вправо. В заголовке каждой таблицы есть общий чек-бокс: отметить все строки или снять все отметки. При частичной отметке он показывает промежуточное состояние, при пустой таблице недоступен. Множественное выделение строк доступно через Ctrl/Shift. Нажатие на чек-бокс выделенной строки применяет новое состояние ко всем выделенным строкам; на невыделенной — только к ней. Пробел на чек-боксе действует так же.

Кнопки неактивны без отметок строк. Подтверждение удаления по умолчанию предлагает отмену. Проверка состава удаления откатывается; реальное удаление допускается только при совпадении состава и отсутствии побочных изменений. Уровни нельзя удалять прямо или через зависимости. Ошибки отображаются явно; транзакции не должны оставлять частично изменённые объекты.

## Существующий перенос

Сохранены стратегии точечных одноуровневых семейств без хоста, горизонтальных перекрытий/потолков и ограниченного набора стен. Условия: [Categories.md](../Categories.md). Неподдержанные элементы не изменяются, причина возвращается пользователю.

Каждый перенос имеет отдельную транзакционную группу. Проверяются уровень, смещение, положение и геометрия после регенерации и фиксации. Изменения других элементов и предупреждения Revit откатывают попытку; критическая ошибка откатывает пакет. Допуск координат `1e-5 ft`, относительный допуск объёма/площади `1e-9`. Консервативные проверки могут отклонять допустимые случаи; алгоритмы в текущей итерации не расширяются.

## Архитектура и проверка

- Один проект `ReLevel.Revit`, одна DLL плагина `ReLevel.Revit.dll`.
- `Logic/` — расчёты, координаты и результаты без Autodesk API внутри того же проекта.
- `Transfer/` — стратегии, анализ и проверки переноса; `UI/` — WPF-интерфейс.
- `ReLevel.addin` в корне репозитория — регистрация команды. Установка вручную описана в README.
- Unit-тесты и отдельный проект Core не используются. Проверки состояния модели и откат во время выполнения сохраняются.
- Алгоритмы, условия применимости и проверки переноса элементов описываются в [Categories.md](../Categories.md), переноса видов — в [Views.md](../Views.md). Реализация должна соответствовать относящимся к задаче правилам этих документов.

Сборка — против локальных DLL Revit 2025. Успешная сборка не подтверждает поведение внутри Revit. Ручная проверка на копии модели должна охватывать перенос и сохранение положения/геометрии, пропуски, выделение, открытие видов, удаление с зависимостями и откат. Автоматических интеграционных тестов и готовой тестовой RVT-модели пока нет.

## Будущее, вне этой итерации

Полный поиск всех связей с уровнем; новые проверенные стратегии; инварианты коннекторов и системных связей MEP; безопасное пересоздание видов с настройками, аннотациями и связями; интеграционные тесты на специальной модели. Расширять поддержку без проверки механизма нельзя.
