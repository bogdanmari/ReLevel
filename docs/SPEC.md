# Цель работы плагина

Глобальная идея ReLevel — убрать зависимости элементов и видов от определённого уровня, чтобы впоследствии пользователь мог удалить этот уровень без потери информации в модели Revit.

- Обработка элементов определяется по отдельным случаям в разделе «Перенос элементов с уровня на уровень».
- Плагин пересоздаёт планы на другом уровне, сохраняя перечисленные ниже настройки и содержимое. Неполный результат должен быть явно обозначен.
- Сам плагин уровни не удаляет. Пересоздание видов не является подтверждением, что уровень полностью освобождён от зависимостей.
- Документ описывает требования. Оставшаяся реализация, вопросы и результаты проверок находятся в [TASKS.md](../TASKS.md).
- Требования проекта относятся к основной линейке `2025+`. Адаптация Legacy выполняется отдельной задачей.

# Новый интерфейс

- Отдельная команда `ReLevel UI Prototype` основной линейки открывает одно изменяемое по размеру окно WPF по центру экрана. Начальный размер — 968×624 единицы WPF (примерно на 18% меньше исходного). Слева сворачиваемая навигация: распределение по уровням, окраска по уровням, перенос; отладка и настройки закреплены внизу под разделителем. В свёрнутом меню остаются собственные иконки с подсказками. В начале раздела — компактный заголовок и описание назначения без третьего мелкого пояснения. Существующая команда и движок сохраняют прежнее поведение.
- Таблицы уровней имеют контрастную шапку и чередование фона строк, сортировку по столбцам (отметка сортируется как число), независимые поиск и фильтр по принципу существующей программы: подстрока без учёта регистра, счётчик, переход стрелками и Enter / Shift+Enter. Поиск охватывает видимые текстовые поля; ID остаётся в подсказке. Общая галочка в шапке отмечает или снимает отметки доступных видимых строк и отображает частичный выбор. Выделение Ctrl/Shift не меняет галочки; галочка выделенной строки применяется ко всему выделению, недоступные ячейки пропускаются. Поиск, фильтр, сортировка и выбор сохраняются при навигации и смене языка.
- Выбор цвета содержит общую палитру с цветовым тоном, насыщенностью и яркостью, готовые образцы и ввод #RRGGBB; результат принимается кнопкой «Применить», отмена сохраняет прежний цвет.
- Кнопки панели поиска используют собственные векторные значки: воронка для фильтра, стрелки вверх/вниз для предыдущего/следующего совпадения. Назначение доступно в локализованных подсказках и именах для средств доступности; недоступные стрелки приглушены.
- Содержимое окна и диалога цвета отображается в масштабе 90%: уменьшаются текст, иконки, отступы и элементы управления. Бирюзовая палитра сохраняется. Сворачивание меню выполняется небольшой малоконтрастной стрелкой на боковой границе. Ширина развёрнутого меню подстраивается под подписи текущего языка без полос прокрутки. Текст выбранного значения и пунктов выпадающих списков выравнивается по вертикальному центру.
- Шапка колонки «Оставить уровень» содержит только общую галочку без подписи Keep Level / «Оставить уровень». Щелчок по заголовку сортируемой колонки переключает возрастание/убывание; щелчок по общей галочке меняет отметки, а не сортировку.
- Только выбранный пункт меню показывает тонкие боковые линии; в каждой из двух групп первый пункт имеет также верхнюю линию, последний — нижнюю. У невыбранных пунктов бортики прозрачны, в том числе при наведении. При сворачивании место блока ReLevel сохраняется, высота пунктов постоянна: иконки и пункты не смещаются по вертикали.
- Активное направление сортировки обозначается стрелкой ▲/▼ рядом с заголовком. Столбцы разделены вертикальными линиями в шапке и строках. Все заголовки, включая «Не переносить элементы с этого уровня» / Do not move elements from this level, имеют одинаковый размер шрифта.
- Команда нового интерфейса работает в TransactionMode.Manual и доступна только в документе проекта, разрешённом для изменения. Историческое имя команды `ReLevel UI Prototype` и класс `PrototypeCommand` сохраняются для запуска. При открытии выбран Transfer. Таблицы распределения/окраски используют снимок уровней: ID, имя и отметка относительно начала проекта в метрах. Принятый интерфейс объединяет операции Transfer, графику активного вида и инструменты отладки.
- Перед открытием нового интерфейса выполняется общий анализ элементов текущей модели по существующим кейсам. На время анализа показывается круговой бирюзовый индикатор и число обработанных кандидатов. Индикатор анимируется в отдельном потоке WPF; обращения к Revit API выполняются только на потоке команды. Классификация и принадлежность уровням сохраняются до закрытия окна и используются разделами без повторного полного анализа при смене уровня, страницы или языка.
- В таблицах распределения/Color, списках Source/Target и подтверждении пересоздания рядом с именем уровня показывается число элементов модели: `Level 1 (42)`. Имя модели не изменяется; сортировка и поиск списков продолжают работать по имени. Счётчик включает элементы, соответствующие отбору существующих кейсов, в том числе закреплённые и с ограничениями записи. Двухуровневый элемент учитывается только на уровне нижней привязки, независимо от числового порядка отметок; каждый ID считается один раз. Принадлежность Transfer сохраняется для обеих привязок. Поэтому счётчик уровня и число строк Transfer могут различаться: счётчик включает закреплённые/недоступные для записи элементы по нижней привязке, а таблица Transfer также показывает элементы с верхней привязкой к выбранному уровню. Виды и элементы связанных моделей в счётчики не входят.
- Число рядом с именем в Color относится ко всей модели; отдельный столбец «На виде» показывает число подходящих элементов активного вида по правилам окраски. После переноса, распределения, удаления, пересоздания видов и добавления ID анализ обновляется с индикатором, сохраняя выбранные уровни и настройки таблиц уровней. Изменение графики не требует повторной классификации всей модели. После критического сбоя новый анализ не запускается.
- Ошибки анализа отдельных ID сохраняются в пояснениях Transfer; неполные счётчики отмечаются `*`, включая в списках уровней. Ошибка чтения не означает нулевое количество элементов. Сбой регенерации прекращает анализ и команду без открытия рабочего окна или повторного чтения повреждённого документа.
- Распределение: «Оставить уровень», имя, отметка, «Не переносить элементы с этого уровня». Защита доступна только сохраняемому уровню. Распределение обрабатывает элементы несохраняемых и незащищённых сохраняемых уровней; сохраняемые уровни принимают элементы. Кнопка доступна при выборе хотя бы одного сохраняемого уровня. Правило выбора цели и выполнения определено в разделе «Распределение по сохраняемым уровням».
- Окраска: выбор уровня, имя, отметка, количество подходящих элементов активного вида, цвет и «Скрыть». Цвет и скрытие доступны только выбранным уровням. Образец открывает выбор цвета; скрытие сохраняет цвет и визуально обозначается. «Применить» обрабатывает все отмеченные уровни, включая скрытые поисковым фильтром: отметка означает «Покрасить» или «Скрыть», отсутствие отметки — «Не менять» по правилам раздела «Цвета по уровням на активном виде». «Сбросить» восстанавливает исходную графику текущего вида и снимает отметки выбора/скрытия, сохраняя цвета. Начальные цвета различаются между уровнями.
- Color открывается внутри общего окна. При первом входе для текущего вида собираются элементы и исходная графика; внизу указаны имя вида и результат операции, подробности ошибок доступны в подсказке. При возврате после Transfer состав и привязки обновляются: удалённые ID исключаются, новые получают собственное исходное состояние, ранее сохранённые переопределения остаются доступными для сброса, включая скрытые этим инструментом элементы. Если Transfer открывает другой вид, для него используется отдельное исходное состояние. Применение и сброс относятся только к активному виду. Во время записи всё окно заблокировано; после ошибки операции окно закрывается без последующего чтения модели. Неподдерживаемый вид отключает кнопки Color с пояснением, остальные разделы доступны.
- Transfer содержит исходный и целевой уровни с поиском, вкладки «Элементы» и «Виды», рабочие таблицы с поиском/фильтром, сортировкой, общими галочками и Ctrl/Shift. Исходный уровень исключён из целей. Произвольный текст и отсутствие другого уровня не позволяют запустить перенос/пересоздание. При смене источника таблицы обновляются, отметки сбрасываются; допустимая прежняя цель сохраняется.
- Во вкладке элементов доступны выделение в модели, удаление и перенос; во вкладке видов — открытие, удаление и пересоздание. Отбор, закреплённые строки, ограничения, подтверждение состава удаления, транзакции, откат, Undo и результаты определяются существующими разделами SPEC. Операции выполняются только для отмеченных видимых доступных строк. Перенос использует цель на странице; пересоздание открывает подтверждение с этой фиксированной целью и редактируемым префиксом. Существующая команда ReLevel сохраняет отдельный выбор цели в диалогах.
- Прогресс переноса/пересоздания находится в Transfer. Во время операции всё окно, включая меню и настройки, заблокировано, кроме кнопки «Отмена»; закрытие запрещено. При критической ошибке прекращается обработка и закрывается всё окно без повторного чтения повреждённого документа. Отчёты и диалоги принадлежат новому окну. Смена страницы сохраняет состояние Transfer.
- Debug содержит рабочие локализованные кнопки выделения по кейсу, добавления по ID и инспектора. Первые две вызывают существующие инструменты, используя общий с Transfer набор добавленных ID и выбранный в Transfer исходный уровень. Инспектор закрывает общее окно и выполняет выбор элемента/запись ELEMENTS.md в контексте команды по прежним правилам. Ранее завершённые операции сохраняются.
- В Transfer описание находится справа от заголовка в одной строке; при недостатке ширины сокращается многоточием с полным текстом в подсказке. Вкладки «Элементы»/«Виды» компактны, вертикальные интервалы сокращены для увеличения доступной высоты таблицы.
- Настройки содержат только русский и английский языки. Перевод применяется сразу к новому интерфейсу. Состояния страниц, выбор и цвета сохраняются при навигации и смене языка в пределах открытого окна. Изменение выбора само по себе не записывает настройки на диск и не меняет модель; операции запускаются соответствующими кнопками. Настройки языка общие с существующей командой на время сеанса; смена языка применяется также к Transfer и последующим диалогам, сохраняя уровни, вкладку, отметки, выделение, сортировку, поиск и фильтр.
- При отключении «Оставить уровень» прежняя отметка защиты сохраняется как неактивный выбор; аналогично неактивны сохранённые цвет и скрытие невыбранного уровня. Начальные отметки выключены. Разделы можно добавлять независимо.

# Распределение по сохраняемым уровням

- Пользователь выбирает сохраняемые уровни. Для каждой обрабатываемой привязки выбирается ближайший сохраняемый уровень снизу по высоте; если ниже нет ни одного — самый нижний сохраняемый. На одинаковых отметках сохраняется текущая привязка к сохраняемому уровню; иначе выбирается уровень с меньшим ID. Допуск сравнения отметок — 1e-9 фута. Если цель совпадает с текущим уровнем, запись не выполняется.
- Для существующих пар «уровень + смещение» используется их суммарная отметка относительно начала проекта. Нижняя и верхняя привязки стен, колонн, Pipe Accessories, лестниц, пандусов и шахтных проёмов получают цели независимо, включая случай общего исходного уровня. Для присоединённых концов используется отметка, выраженная параметрами соответствующего кейса; новая геометрическая интерпретация присоединения не добавляется. Для внутренних стен In-Place действует только нижняя привязка.
- Для остальных одноуровневых случаев используется точка размещения; для балки — нижняя из отметок концов относительно Reference Level; для помещения — отметка уровня с Base Offset; для линий и элементов с LocationCurve — нижняя отметка точек разбиения кривой. У хостовых ограждений, Fabrication/Flex-элементов без доступной точки/кривой берётся нижняя отметка габарита модели. Отсутствие доступной высоты даёт ошибку с ID, без подстановки отметки исходного уровня. Этот выбор высоты служит только определению цели, а перенос выполняется существующим кейсом.
- «Не переносить элементы с этого уровня» сохраняет привязки к защищённому сохраняемому уровню. Такой уровень по-прежнему принимает другие элементы. Неактивная защита несохраняемого уровня не действует. Выбор сохраняемых/защищённых уровней учитывается во всей таблице, включая строки, скрытые поиском. Поиск и исходный уровень Transfer не ограничивают распределение.
- Область обработки — распознанные общим анализом элементы существующих кейсов текущей модели и добавленные через Debug ID. Элементы связей не включаются. Перед записью кейс и ограничения проверяются вновь: закрепление, доступность записи, группы/сборки, поддержка пересоздания и допустимые зависимости. Неподдерживаемые при повторной проверке кандидаты и защищённые/уже подходящие привязки отражаются в отчёте как пропуски; ошибки чтения/записи — как ошибки. Новые случаи этим инструментом не вводятся.
- Виды не пересоздаются распределением и остаются отдельной операцией Transfer; уровни не удаляются. Для помещений и границ применяется именно существующий алгоритм пересоздания соответствующего кейса со всеми его ограничениями и сообщением о новом ID.
- Изменения обеих привязок одного элемента выполняются в одной транзакции. При обычной ошибке весь текущий элемент откатывается, обработка следующих продолжается. Сбой регенерации/критический отказ или невозможность завершить откат останавливают пакет: оставшиеся ID отмечаются необработанными, окно закрывается без повторного чтения модели. Предыдущие успешно завершённые элементы сохраняются. Undo выполняется по транзакциям элементов, как в Transfer.
- Во время операции всё окно, кроме кнопки «Отмена» справа от прогресса, заблокировано и закрытие запрещено. На странице показан прогресс по кандидатам, включая пропуски и ошибки. После операции открывается общая таблица результатов с ID, статусом, причиной и переходами между уровнями; доступны копирование и TSV. После нормального завершения Transfer обновляет состав и снимает отметки строк, а Color при следующем входе обновляет привязки. Выбор сохраняемых и защищённых уровней остаётся в таблице.

# Основное окно интерфейса

- Технология: WPF.
- Начальная ширина: 920 единиц WPF.
- Начальная высота: 607,2 единицы WPF.
- Положение при открытии: центр экрана.
- Верхний блок: выбор исходного уровня и языка. Режим «Работать с выбранными элементами» отключён и не показывается.
- Под верхним блоком — независимые инструменты отладки «Выделить все элементы по…» и рядом «ReLevel инспектор».
- Основной блок: две вкладки — «Элементы» и «Виды».
- В каждой вкладке: отдельная таблица, поиск и кнопки операций.
- Кнопки вкладки «Элементы»: «Выделить элементы», «Удалить элементы», «Перенести элементы».
- Кнопки вкладки «Виды»: «Открыть виды», «Удалить виды», «Пересоздать виды».
- Кнопки операций с таблицей расположены справа под ней. Без отмеченных видимых строк они недоступны. Инструменты отладки не требуют отметок в таблице.
- Состояние таблиц хранится до закрытия окна. История автоматически не записывается на диск или в параметры проекта.
- При переносе элементов и пересоздании видов внизу окна показываются полоса прогресса, число обработанных из общего количества, текущий ID и прошедшее время. Счётчик включает завершённые попытки с ошибками и пропусками, а не только успешные результаты. После критической остановки оставшиеся необработанные элементы или виды не увеличивают прогресс. Обновление выполняется до и после обработки элемента или вида; внутри длительного вызова Revit счётчик и время не обновляются. Для вида учитываются все этапы, включая размещение на листе. После завершения остаётся итоговая строка. На время операции управление окном, кроме кнопки «Отмена» справа от прогресса, и закрытие блокируются; операции API остаются на основном потоке. Прогресс удаления и открытия видов не показывается.

- Во время переноса элементов, распределения и пересоздания видов справа от прогресса видна кнопка «Отмена» / Cancel. Она останавливает запуск на ближайшей границе между элементами или видами и откатывает все изменения этого запуска, включая завершённые транзакции. Текущий вызов Revit не прерывается. Ранее завершённые запуски сохраняются. Повторное нажатие блокируется; по окончании кнопка скрывается. Отчёт после отмены не содержит успешных результатов или действительных ID отменённых новых видов; таблицы и счётчики обновляются после успешного отката. Ошибка отката обрабатывается как критическая, без обновления модели.

# Язык интерфейса

- Доступные языки: `English / Русский`.
- При первом запуске команды в сеансе язык определяется по интерфейсу Revit: русский → Русский; английский → English; остальные языки → English.
- Выбор пользователя сохраняется до завершения сеанса Revit и не сбрасывается при повторном открытии команды.
- Смена языка применяется сразу к интерфейсу и последующим диалогам, сообщениям и журналам.
- При смене языка сохраняются уровень, вкладка, отметки, выделение строк, сортировка, поиск и фильтр.
- Имена объектов модели, пользовательский ввод, исходные сообщения Revit и готовые результаты операций не переводятся.

# Выбор уровня

- Пользователь выбирает исходный уровень. Вкладка «Виды» показывает связанные с ним виды; правила заполнения таблицы элементов описаны ниже.
- Исходное выделение Revit не используется для заполнения таблиц. Действия «Выделить элементы», выделение по кейсу и инспектор доступны независимо от него.
- Смена уровня обновляет таблицы и сбрасывает отметки и результаты предыдущей операции.
- Все списки уровней допускают поиск по части имени без учёта регистра. Пункты отсортированы по имени.
- Пустой запрос показывает все уровни. После выбора повторное открытие списка снова показывает все варианты.
- Для операции нужно выбрать существующий уровень; произвольный текст выбором не считается.
- Enter в раскрытом списке выбирает пункт, но не запускает операцию. Escape закрывает список.

# Таблицы и поиск

- Выделение строки и отметка чек-боксом — разные действия. Операции выполняются только для отмеченных видимых строк.
- Ctrl/Shift позволяют выделить несколько строк.
- Чек-бокс или пробел на выделенной строке применяет новое состояние ко всему выделению; на невыделенной — только к этой строке.
- Общий чек-бокс отмечает все доступные для отметки видимые строки и показывает частичную отметку. Заблокированные строки пропускаются при одиночной и массовой отметке.
- Поиск работает по видимым текстовым колонкам, включая ID, по подстроке без учёта регистра.
- Счётчик показывает число совпадений. Стрелки и Enter / Shift+Enter циклически переходят по ним в порядке таблицы, не устанавливая отметки.
- «Фильтр» оставляет только совпадения. Пустой запрос показывает все строки.
- При обновлении таблицы запрос и режим фильтра сохраняются, отметки сбрасываются.
- Отметки скрытых строк сохраняются до обновления данных, но в операциях не участвуют.
- После операции таблица обновляется. Результат показывается по ID, в том числе для объектов, исчезнувших из таблицы.

# Вкладка «Элементы»

- Сохраняются таблица, поиск, фильтр и кнопки «Выделить элементы», «Удалить элементы», «Перенести элементы».
- Колонки: отметка, ID, категория, имя элемента, привязка, статус. Привязка показывает «Уровень» для Кейсов 1 и 4, «Низ», «Верх» или «Низ и верх» для Кейсов 2, 9, 14 и 15 относительно исходного уровня, «Уровень спецификации» для Кейса 3.
- Список строится по реализованным случаям переноса — Кейсам 1–21. Элемент должен соответствовать условиям случая и принадлежать исходному уровню. Незакреплённые элементы с ограничениями записи в таблицу не добавляются. Закреплённые элементы поддержанных кейсов показываются независимо от ограничений записи: галочка недоступна, статус сообщает «Элемент закреплён. Перенос недоступен.». Отметка мышью, пробелом, для нескольких строк, через «Отметить все» и восстановление отметок после смены языка пропускают закреплённые строки. Состояние общей галочки учитывает только доступные для отметки видимые строки. Снимки результата и геометрии при заполнении таблицы не создаются.
- Перед переносом каждого элемента закрепление повторно проверяется независимо от кейса; закреплённый экземпляр пропускается с причиной. Плагин не снимает закрепление. Ограничения закрепления в описаниях кейсов относятся к записи, а не к отображению строки.
- Принадлежность определяется параметрами уровня соответствующего случая. Поиск других прямых или косвенных связей с уровнем здесь не выполняется; общий сбор таких элементов будет отдельным инструментом.
- Доступность в списке означает соответствие условиям отбора, а не гарантированный успех записи на произвольную цель. Ошибка чтения экземпляра исключает его из списка; число таких ошибок и подробности с ID показываются в сводке и её подсказке.
- «Выделить элементы» устанавливает выделение отмеченных видимых строк в Revit.
- «Перенести элементы» выполняет перенос отмеченных видимых строк на выбранную цель: в старом окне она выбирается в диалоге, в новом — на странице Transfer. Источник исключён из списка целей. Результаты выводятся в отдельном изменяемом по размеру окне таблицей с тремя колонками: `ID`, `Status`, `Information` (заголовки одинаковы для обоих языков). Каждому результату соответствует строка: ID элемента, локализованный статус «Перенесён», «Пропущен» или «Ошибка», полное пояснение. Длинные пояснения переносятся по строкам; доступно копирование выбранных строк с заголовками через Ctrl+C. Над таблицей показывается сводка, а при критической остановке — также предупреждение. После обычного завершения основная таблица обновляется; при критической остановке окно закрывается после просмотра результатов без обновления модели.
- «Удалить элементы» удаляет отмеченные видимые строки после проверки зависимостей и подтверждения состава удаления по правилам ниже.
- Таблица результатов переноса использует оформление нового интерфейса: бирюзовая шапка, разделители, чередование строк и сортировка со стрелками. «Копировать всё» копирует весь отчёт, Ctrl+C — выделенные строки; оба варианта включают заголовки ID/Status/Information. «Экспорт в TSV» сохраняет весь отчёт в текущем порядке таблицы, UTF-8 с BOM, через выбор файла и подтверждение замены. Табуляции, переводы строк и кавычки в полях экранируются без потери текста. Отмена сохранения не записывает файл; ошибки копирования/записи явно показываются и не закрывают отчёт.
- Отбор, определение уровня, перенос и проверка элементов описываются отдельно для каждого случая ниже.

# Инструмент отладки «Выделить все элементы по…»

- Кнопка открывает выбор из реализованных кейсов переноса — Кейсов 1–21. Нереализованные случаи в список не включаются.
- После выбора кейса и нажатия «Выделить» выполняется поиск по всей текущей модели, на всех уровнях. Активный вид, исходный уровень окна, отметки, поиск и фильтр таблицы не ограничивают поиск.
- Используются условия принадлежности выбранному кейсу из его реализации. Отдельные проверки возможности записи и создания геометрического снимка не применяются. Подходящие кейсу экземпляры с параметром только для чтения или закреплённые тоже выделяются для отладки.
- Содержимое связанных документов не обходится. Инструмент меняет только выделение Revit, без переноса и изменения параметров модели.
- Найденный набор заменяет текущее выделение. После установки проверяется фактическое выделение Revit; показываются число найденных и выделенных экземпляров, ошибки чтения и ID объектов, которые Revit не включил в выделение.
- Если совпадений нет или пользователь отменил выбор кейса, текущее выделение сохраняется. Ошибка чтения одного экземпляра записывается с ID, поиск остальных продолжается; критический сбой прекращает команду.
- Состояние таблиц и выбранный уровень окна не изменяются. Окно ReLevel остаётся открытым; чтобы работать с выделением в модели, пользователь закрывает его.

# Добавление элементов по ID

Кнопка «Добавить по ID» в основном окне позволяет включить в кандидаты текущего сеанса элементы, недоступные для обычного выделения и сбора Revit. ID вводятся через запятую, пробел, точку с запятой или перенос строки. Чтение выполняется через Document.GetElement; модель и выделение не меняются. В таблицу попадают элементы реализованных кейсов, связанные с выбранным уровнем: доступные для записи и закреплённые. У закреплённых строк галочка заблокирована и указана причина. Для отсутствующих/неподдержанных/непринадлежащих уровню ID и ограничений записи показываются пояснения. ID хранятся до закрытия окна и учитываются при смене уровня, языка, обновлении таблицы и отладочном выборе по кейсу; совпадения не дублируются. Поддержанные ID вне выбранного уровня остаются кандидатами для других уровней. Обновление сбрасывает отметки строк по общим правилам.

# Инструмент отладки «ReLevel инспектор»

- Кнопка рядом с «Выделить все элементы по…» закрывает окно ReLevel и предлагает выбрать один элемент в модели. Выбор не ограничивается реализованными кейсами, уровнем или таблицей. Используется элемент текущего документа; содержимое связанных документов отдельно не выбирается.
- После выбора снимок дописывается в конец [ELEMENTS.md](../ELEMENTS.md) в корне этого проекта. Повторный выбор создаёт новую запись; предыдущие снимки и ручные заметки сохраняются. Escape отменяет выбор без записи. Для следующего элемента пользователь снова открывает ReLevel.
- Путь к папке проекта фиксируется при сборке основной версии. Установленная DLL записывает отчёты по этому пути. Если папка перенесена, плагин нужно пересобрать; недоступность папки или файла показывается как ошибка, без записи в другое место.
- Снимок содержит время с часовым поясом, версию и сборку Revit, название и путь модели, ID и UniqueId, класс API, категорию и тип элемента, LevelId, размещение, закрепление, группу, сборку, вариант, рабочий набор, вид-владелец и фазы.
- Для FamilyInstance записываются семейство, способ размещения, свойство Host (не параметр), HostFace, вложенность, повороты и ориентация. Отдельно записываются параметры экземпляра и типа: ID и имя BuiltInParameter, имя параметра, GUID общего параметра, тип данных, доступность записи, сырое и форматированное значения, единицы. Ссылки ElementId по возможности разрешаются в элементы и уровни с отметками.
- Также записываются результат проверки принадлежности реализованным кейсам, непосредственные зависимости через GetDependentElements и доступные MEP-коннекторы. Для несущих колонн отдельно читаются присоединения низа/верха через ColumnAttachment, соединения геометрии и внешние подрезки/вырезы. Эти сведения не означают подтверждение возможности переноса или полный анализ зависимостей. Геометрия тела целиком не выгружается.
- Значения чисел API сохраняются без округления, с десятичной точкой; длины и координаты — в футах, углы — в радианах. Подписи структуры отчёта остаются на русском с именами API, значения модели и форматированные значения Revit сохраняют исходный язык.
- Ошибка чтения свойства явно отмечается в отчёте; остальные доступные данные сохраняются. Критический сбой Revit прекращает чтение без записи снимка. После успешной записи показываются ID элемента, путь файла и количество ошибок чтения. Ошибка записи не должна оставлять частичный снимок, если файловая система позволяет восстановить прежнюю длину файла; ошибка такого восстановления также сообщается.
- Инспектор только читает модель, без транзакций, переноса или пробного удаления. Ранее завершённые операции ReLevel сохраняются. Запись в файл не запускает анализ агентом автоматически: снимки используются при последующем обсуждении и согласовании кейсов в SPEC.

# Цвета по уровням на активном виде

- В существующей команде кнопка «Цвета по уровням» закрывает главное окно и открывает отдельное окно для текущего вида. Оно показывает уровни, количество подходящих элементов и действия «Не менять», «Покрасить», «Скрыть». По умолчанию все уровни имеют действие «Не менять». Для «Покрасить» рядом появляется образец случайного цвета; цвет уровня сохраняется в течение открытого окна. В новом интерфейсе эти действия представлены таблицей Color и кнопками применения/сброса в общем окне.
- Обрабатываются элементы текущего документа, полученные коллектором активного вида и соответствующие условиям отбора существующих кейсов переноса. Ограничения записи параметров уровня и закрепление не исключают элемент из инструмента графики. Элементы связанных моделей не включаются. У двухуровневых элементов используется только нижняя привязка, включая колонны, стены, Pipe Accessories, лестницы, пандусы и шахтные проёмы. У остальных — источник, определённый соответствующим кейсом. Выбор исходного уровня, поиск и отметки основной таблицы не ограничивают инструмент.
- «Применить» меняет индивидуальную графику только этого вида: цвет линий проекции и сечения, сплошную переднюю заливку поверхностей и сечений. Прочие исходные переопределения сохраняются. «Скрыть» выполняет постоянное скрытие элементов на виде; элементы, которые Revit запрещает скрывать, пропускаются с указанием количества и ID. Геометрия, параметры привязки, фильтры вида и шаблон не изменяются.
- Исходные индивидуальные переопределения и скрытие сохраняются на время открытого окна. Каждое применение рассчитывается относительно этого состояния. «Не менять» возвращает исходное состояние ранее обработанных в этом окне элементов уровня; ещё не обработанные не изменяются. «Сбросить» восстанавливает исходное состояние всех затронутых элементов и сбрасывает действия уровней. В отдельном старом окне набор фиксируется при открытии. Новый общий интерфейс обновляет состав после операций других разделов, сохраняя исходную графику ранее захваченных ID. Скрытые этим окном элементы доступны для последующего сброса.
- Закрытие сохраняет применённые изменения; после закрытия восстановление — через Undo Revit. Новое окно начинает отсчёт от текущего состояния вида. Каждое применение/сброс — одна транзакция и один Undo; ошибка откатывает всю незавершённую операцию. После сбоя окно закрывается, при критической ошибке дальнейшее чтение модели не выполняется. Виды без поддержки графических переопределений отклоняются до изменений; ошибки чтения отдельных элементов показываются с ID.

# Перенос элементов с уровня на уровень

На текущем этапе каждый кейс содержит отбор объектов и алгоритм переноса. Автоматического сравнения результата с исходным состоянием нет: геометрия, значения параметров после записи, положение и изменения других объектов не проверяются. Сохраняются обработка отказов API и управление транзакциями. Сообщение об успехе означает выполнение алгоритма и успешный Commit. Общий механизм проверки результатов для тестирования разрабатывается отдельно после всех кейсов.

## Случай 1. Одноуровневое загружаемое семейство без хоста с точечным размещением

### Отбор элементов

- Рассматриваются экземпляры `FamilyInstance` текущего документа проекта. Семейство загружаемое: `instance.Symbol.Family.IsInPlace == false`.
- Способ размещения: `instance.Symbol.Family.FamilyPlacementType == FamilyPlacementType.OneLevelBased`. Это явная проверка одноуровневого семейства; наличия одного `FAMILY_LEVEL_PARAM` недостаточно для классификации способа размещения. Семейства `TwoLevelsBased` в этот случай не входят. Значения перечисления описаны в [Revit API — FamilyPlacementType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2abb8627-1da3-4069-05c9-19e4be5e02ad.htm).
- Проверяется свойство `instance.Host`: оно должно быть `null`. Текстовый параметр «Host» / «Основа» для этой проверки не используется.
- Экземпляр самостоятельный: `instance.SuperComponent == null`. Перенос вложенных экземпляров отдельно от родительского семейства относится к другому случаю.
- `instance.Location` должен быть доступен как `LocationPoint`. Экземпляры с `LocationCurve`, другим типом `Location` или без положения в этот случай не входят.
- Параметр `instance.get_Parameter(BuiltInParameter.FAMILY_LEVEL_PARAM)` существует, имеет тип хранения `StorageType.ElementId`, а его значение указывает на существующий `Level` текущего документа. Поиск параметра по локализованному имени не используется.
- Принадлежность случаю и возможность выполнить запись проверяются отдельно: недоступный для записи параметр уровня или невозможность изменить положение не разрешаются принудительно; перенос не выполняется либо откатывается с ID и причиной.

### Определение принадлежности уровню

- Единственный источник принадлежности уровню для этого случая — `FAMILY_LEVEL_PARAM.AsElementId()`.
- В режиме исходного уровня экземпляр относится к выбранному уровню, если ID из параметра равен ID выбранного уровня.
- Координата Z, имя уровня и расположение геометрии между уровнями не используются для определения принадлежности. Экземпляр со смещением от уровня всё равно принадлежит уровню, записанному в параметре.
- Если параметр уже указывает на целевой уровень, запись не требуется; экземпляр не считается заново перенесённым.

### Способ переноса

Для Air Terminals (OST_DuctTerminal), соответствующих отбору Кейса 1, применяется запись пары FAMILY_LEVEL_PARAM / INSTANCE_ELEVATION_PARAM через LevelOffsetOperation: до изменений сохранить исходную отметку уровня и смещение, назначить целевой уровень и смещение = исходное смещение + исходный ProjectElevation − целевой ProjectElevation. Между записями нет явной регенерации; LocationPoint и коннекторы не назначаются. Требуются незакреплённый экземпляр и заданный writable Double-параметр Elevation from Level. При отсутствии этой возможности элемент исключается, без возврата к переносу с промежуточным сдвигом. Кейс 19 Fabrication Parts этим правилом не затрагивается.

Для остальных семейств Кейса 1:

1. До записи сохранить ID экземпляра и координаты его точки размещения.
2. Открыть одну Transaction для экземпляра.
3. Записать целевой ID в FAMILY_LEVEL_PARAM через Parameter.Set.
4. Выполнить Document.Regenerate(), чтобы Revit пересчитал размещение после смены уровня.
5. Заново получить LocationPoint экземпляра и назначить сохранённую точку. Это часть переноса; сравнения с исходной точкой и проверки угла нет. Угол намеренно не назначается. Отдельный параметр смещения не используется.
6. Выполнить Commit. Повторный явный Regenerate не нужен: Commit пересчитывает документ автоматически. См. [Document.Regenerate](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/22468e2c-9772-8478-0816-c9759aa43428.htm).
7. Отказ записи или исключение API отменяет незавершённую транзакцию этого экземпляра. При критическом сбое регенерации или отката пакет прекращается без дальнейшего чтения модели.

Каждый успешный экземпляр отменяется одним Undo. Ранее завершённые переносы сохраняются. Ошибки Revit, не разрешённые через Unjoin по общей политике ниже, приводят к откату текущей операции; предупреждения обрабатываются обычным диалогом Revit. Для возможности полной отмены запуска транзакции элементов заключаются в TransactionGroup: обычное завершение через Commit группы сохраняет отдельные Undo, отмена пользователем откатывает всю группу. Проверки после Commit для переноса не используются.

## Общая политика Unjoin при переносе элементов

- Для всех реализованных кейсов при ошибке или предупреждении невозможности сохранить соединение допускается штатное разрешение Revit `DetachElements` (Unjoin). Оно применяется только к встроенным сообщениям `CannotKeepJoined`, `CannotJoinElementsWarn`, `CannotJoinElements`, `CannotJoinElementsError`, `CannotJoinElementsMultiPlaneError`, `CannotJoinElementsStructural`, `CannotJoinElementsStructuralError`, если Revit предоставляет и разрешает именно `DetachElements`. Сравнение выполняется по идентификатору ошибки, не по локализованному тексту.
- Перенос и Unjoin выполняются в одной транзакции. Разрешение может затронуть соседние элементы, не выбранные для переноса. Предварительное разъединение всех связей не выполняется; автоматическое удаление элементов, снятие ограничений и другие разрешения ошибок не применяются.
- При успешном Commit сообщение о переносе обязательно содержит `Unjoined` и ID участников разрешённых ошибок, включая дополнительные ID Revit. Это список участников, а не перечень точных пар разорванных соединений. Изменение геометрии вследствие Unjoin допускается и отдельно не проверяется; соединения автоматически не восстанавливаются. Перенос вместе с Unjoin отменяется одним Undo.
- Остальные ошибки, отсутствие доступного Unjoin или повторение той же ошибки после попытки разрешения приводят к откату всей операции элемента, включая уже выполненные разъединения. Число проходов разрешения ограничено восемью. При откате сообщение об успешном Unjoin не выводится. Критические ошибки регенерации и отката прекращают пакет; обычные предупреждения, не относящиеся к указанным сообщениям Join, сохраняют штатную обработку Revit. При откате сохраняются полученные сообщения Revit, включая предупреждения: текст, severity, FailureId, основные и дополнительные ID, доступность разрешённого Unjoin.

## Случай 2. Колонны и стены

### Отбор элементов

- Вариант колонны охватывает загружаемые несущие и архитектурные колонны `FamilyInstance` категорий `OST_StructuralColumns` и `OST_Columns`, с `FamilyPlacementType.TwoLevelsBased`.
- Кейс также охватывает загружаемые `FamilyInstance` категории `OST_PipeAccessory` с `FamilyPlacementType.TwoLevelsBased` и `LocationPoint`: без Host, HostFace, SuperComponent, вложенных экземпляров, группы и сборки, без внешних void-вырезов. Для них используются те же нижняя и верхняя FAMILY-пары и алгоритм компенсации смещений ниже. Проверки Column Style, ColumnAttachment, coping и соединений концов колонн к Pipe Accessories не применяются. ID сохраняется; Location, SCHEDULE_LEVEL_PARAM и дополнительные параметры семейства отдельно не записываются. Меняются только пары, совпавшие с исходным уровнем, включая обе при совпадении; другой конец сохраняется. Автоматические проверки результата в операцию не добавляются.
- Обычная вертикальная колонна: `IsSlantedColumn == false`, размещение — `LocationPoint`. Для несущей колонны дополнительно требуется `SLANTED_COLUMN_TYPE_PARAM == 0`; у архитектурной колонны этот параметр не требуется. Также допускается геометрически вертикальная несущая колонна в режиме Slanted — End Point Driven: `IsSlantedColumn == true`, `SLANTED_COLUMN_TYPE_PARAM == 2`, `LocationCurve` с ограниченной прямой Line; горизонтальное расстояние между концами не более 1e-9 ft, разница Z по модулю больше 1e-9 ft. Фактически наклонные колонны и Angle Driven пока исключаются. Свойства `Host`, `HostFace`, `SuperComponent` пустые. Экземпляр не входит в группу или сборку и не имеет вложенных экземпляров.
- Для допускаемого End Point Driven используются те же FAMILY-пары уровня/смещения и компенсация разницы ProjectElevation. Column Style, LocationCurve, расширения и стили подрезки концов не назначаются. Положение концов сохраняется переносом привязок с компенсацией смещений; проверки геометрии внутри операции не выполняются.
- Нет присоединения низа через `ColumnAttachment.GetColumnAttachment(instance, 0)`. Присоединённый верх допускается у несущей колонны OST_StructuralColumns. У архитектурной OST_Columns с присоединённым верхом допускается только перенос нижней привязки, если верхний уровень отличается от исходного; перенос верхней привязки, включая совпадение обоих уровней с исходным, пока исключается. Присоединения проверяются для экземпляров с `ColumnAttachment.IsValidColumn == true`. Нет coping, внешних void-вырезов и соединений концов. Отсутствие Host не заменяет эти условия. См. [ColumnAttachment](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2cf91eab-b1ab-f6e1-8816-23146ded3484.htm).
- Наличие зависимых элементов, соединений геометрии JoinGeometry и твердотельных вырезов SolidSolidCut само по себе колонну не исключает. Перенос использует те же пары уровня/смещения; связи не пересоздаются и отдельно не редактируются, кроме разрешения ошибки соединений через Unjoin по общей политике ниже. Соседние стены и другие объекты не добавляются в пакет переноса автоматически. Их пересчёт выполняет Revit при Commit; проверки результата не выполняются.
- Наличие аналитической связи (`ANALYTICAL_ELEMENT_HAS_ASSOCIATION = 1`) само по себе не исключает колонну. Перенос меняет пары уровня/смещения физической колонны; аналитические элементы, их привязки и ассоциация отдельно не редактируются и не пересоздаются. Перенос аналитической модели на целевой уровень не входит в этот кейс.
- Нижняя привязка: `FAMILY_BASE_LEVEL_PARAM` и `FAMILY_BASE_LEVEL_OFFSET_PARAM`; верхняя: `FAMILY_TOP_LEVEL_PARAM` и `FAMILY_TOP_LEVEL_OFFSET_PARAM`. Уровни существуют в текущем документе; абсолютная отметка верха выше низа. Параметры SCHEDULE не записываются отдельно.
- Вариант стены охватывает `Wall` с `WallType.Kind` Basic или Curtain и `CrossSection == WallCrossSection.Vertical`. Стена не входит в составную стену, группу или сборку. Низ не присоединён: `WALL_BOTTOM_IS_ATTACHED` не равен 1. Присоединённый верх (`WALL_TOP_IS_ATTACHED == 1`) допускается; присоединение сохраняется. Наклонные и составные стены в этот вариант не входят.
- Для стены нижняя привязка — `WALL_BASE_CONSTRAINT` и `WALL_BASE_OFFSET`. Если `WALL_HEIGHT_TYPE` указывает на существующий Level, используется также верхняя пара `WALL_HEIGHT_TYPE` / `WALL_TOP_OFFSET`. Если он равен InvalidElementId (Unconnected), у стены одна нижняя привязка; `WALL_USER_HEIGHT_PARAM`, `WALL_HEIGHT_TYPE` и `WALL_TOP_OFFSET` не записываются. Непривязанная высота сохраняется. Уровни используемых привязок существуют в текущем документе, их смещения доступны для чтения. Наличие эскиза, размеров, соединений или других зависимостей само по себе стену не исключает. Эскиз и Location стены отдельно не редактируются. Для хостовых семейств восстанавливается точка размещения по алгоритму ниже.
- Перед переносом экземпляр не закреплён, параметры уровня и смещения каждого изменяемого конца доступны для записи. Исключение: у присоединённого верха несущей колонны требуется запись только уровня, Top Offset может быть readonly. Принудительное снятие закрепления и удаление зависимостей не выполняются. Разъединение допускается только для разрешения ошибки соединений по общей политике Unjoin ниже.

### Определение принадлежности уровню

- Элемент относится к исходному уровню, если нижний или верхний параметр уровня соответствующего варианта указывает на него. Проверяются ID, а не имена, Location.Z или Element.LevelId.
- Совпадающие привязки отображаются как «Низ», «Верх» или «Низ и верх». Если обе указывают на источник, изменяются обе. Привязка к другому уровню сохраняется.
- У стены с Unconnected принадлежность определяется только нижним уровнем, подпись — «Низ». Верхняя пара не читается для расчёта смещения и не проверяется на доступность записи.

### Способ переноса

1. До записи сохранить ID экземпляра и используемые пары уровень/смещение: две для колонны или стены с верхним уровнем, одну нижнюю для стены с Unconnected. Для стены также найти в текущем документе непосредственные `FamilyInstance` с `Host.Id == wall.Id` и пустым `SuperComponent`; сохранить ID и `LocationPoint.Point`. Поиск не ограничивается выбором для переноса, уровнем семейства или принадлежностью Кейсу 3. Из восстановления точек исключаются элементы сетки витража по `CurtainGrid.GetPanelIds()` и `GetMullionIds()`, включая семейства дверей, установленные в ячейки. Панели, двери в ячейках, импосты и сетка пересчитываются Revit вместе с витражной стеной; их точки и параметры отдельно не назначаются. Если у обычного непосредственного хостового семейства нет LocationPoint, перенос этой стены завершается ошибкой до записи; отдельный алгоритм для других способов размещения пока не реализован.
2. Для присоединённого верха несущей колонны, связанного с исходным уровнем, менять только FAMILY_TOP_LEVEL_PARAM: Top Offset пересчитывает Revit. Его значение читается для отбора, но не рассчитывается и не записывается при переносе. ColumnAttachment, его цель, CutStyle, Justification и Offset From Attachment отдельно не изменяются. Для остальных концов, связанных с исходным уровнем, вычислить `новое смещение = старое смещение + старый Level.ProjectElevation − целевой Level.ProjectElevation` во внутренних единицах Revit. Для стены с присоединённым верхом и верхним уровнем расчёт сохраняет номинальную высоту `H = (верхний ProjectElevation + Top Offset) − (нижний ProjectElevation + Base Offset)`, соответствующую исходному Unconnected Height. Компенсируются все привязки, совпадающие с источником, в том числе обе, если уровни низа и верха одинаковы. Фактическая отметка присоединённой геометрии для расчёта не используется; отсоединение и прямая запись readonly Unconnected Height не выполняются. Для Unconnected остаётся прежний перенос только нижней пары без записи высоты.
3. Открыть одну Transaction. Записать целевой ID и рассчитанное смещение только для совпадающих концов; для присоединённого верха несущей колонны записать только ID уровня. Все пары записываются в одной транзакции; другой конец не назначается заново. Location самой стены или колонны не назначается.
4. Если у стены найдены хостовые семейства, выполнить один Regenerate после назначения всех пар стены, затем восстановить сохранённые точки через `LocationPoint.Point`. Это часть переноса, без сравнения положения до/после. Параметры уровня семейства не записываются; хост, грань, угол и закрепление не переназначаются. Вложенные экземпляры следуют за родительским семейством и отдельно не обрабатываются. Для колонн и стен без таких семейств явный Regenerate не вызывается.
5. Выполнить Commit. Ошибка записи привязок или восстановления точки отменяет всю незавершённую транзакцию этой стены вместе с изменениями её семейств. Ошибки Revit, не разрешённые через Unjoin по общей политике ниже, приводят к откату, предупреждения обрабатываются обычным диалогом Revit. Критический сбой регенерации или отката прекращает пакет без дальнейшего чтения модели. Предыдущие успешные переносы сохраняются; стена вместе с восстановлением точек отменяется одним Undo.

Невыбранные хостовые семейства не добавляются в пакет самостоятельного переноса: для них восстанавливается только положение. Уровень семейства меняется только при его отдельном выборе, своим кейсом. Если семейство уже перенесено раньше стены в том же пакете, восстановление его точки не перезаписывает назначенный уровень; если оно следует за стеной, его операция использует восстановленное размещение.

Снимки геометрии, сравнение исходного и полученного состояния, отслеживание DocumentChanged и контрольные прогоны при переносе не выполняются. Чтение диагностических снимков отдельным инспектором остаётся доступным.

## Случай 3. Семейство на грани хоста

### Отбор элементов

- Загружаемое семейство `FamilyInstance`, не In-Place, с `FamilyPlacementType.WorkPlaneBased`, `LocationPoint` и без `SuperComponent`. Экземпляр не входит в группу или сборку.
- Свойство `Host` задано и не является `RevitLinkInstance`; `HostFace` задано, `HostFace.LinkedElementId == ElementId.InvalidElementId`. Первый вариант охватывает размещение на грани хоста текущего документа. Размещение на грани связанной модели и на свободной рабочей плоскости требует отдельного рассмотрения.
- `INSTANCE_SCHEDULE_ONLY_LEVEL_PARAM` имеет тип ElementId и указывает на существующий Level; `INSTANCE_ELEVATION_PARAM` имеет тип Double и значение. Категория и имя семейства не определяют принадлежность кейсу.
- Перед переносом экземпляр не закреплён, оба параметра доступны для записи. Если Elevation from Level недоступен для записи, экземпляр не предлагается для переноса. По [описанию Autodesk](https://help.autodesk.com/cloudhelp/2023/ENU/Revit-Customize/files/GUID-AB9E985D-3D4B-44AA-82BA-1303D0693A77.htm), доступность этого параметра у семейств на грани зависит от ориентации поверхности.

### Определение принадлежности уровню

- Используется только `INSTANCE_SCHEDULE_ONLY_LEVEL_PARAM` (Schedule Level). Его ID сравнивается с исходным уровнем. `Element.LevelId`, уровень хоста и доступный только для чтения `SCHEDULE_LEVEL_PARAM` не используются для определения принадлежности или записи.
- В таблице привязка обозначается «Уровень спецификации».

### Способ переноса

1. До записи сохранить ID экземпляра, исходный Schedule Level и Elevation from Level.
2. Рассчитать `новая высота от уровня = старая высота от уровня + старый Level.ProjectElevation − целевой Level.ProjectElevation` во внутренних единицах Revit.
3. В одной Transaction записать целевой уровень в `INSTANCE_SCHEDULE_ONLY_LEVEL_PARAM`, затем рассчитанную высоту в `INSTANCE_ELEVATION_PARAM`.

- Воздуховод не пересоздаётся, коннекторы не отсоединяются и не переподключаются кодом. Соседние элементы отдельно не редактируются и не добавляются в пакет автоматически. Действуют общие правила ошибок, отката и Undo. Проверки положения, зависимостей и связности выполняются отдельно на копии модели, не внутри рабочей операции.

Временная политика удаления размеров для хостовых ограждений сюда не распространяется. Действуют общие правила ошибок, отката и Undo. Проверки положения, вырезов и зависимостей выполняются отдельно в Revit, без снимков/проверок результата в рабочей операции.

## Случай 17. Пересоздание помещений Room

- Помещение исходного уровня пересоздаётся с новым ID, исходное удаляется в той же транзакции после переноса значений. Ошибка создания, записи или удаления откатывает всю замену; один Undo отменяет одно успешное пересоздание. Rooms отбираются по категории OST_Rooms и LevelId, включая неразмещённые записи, у которых LevelId ещё указывает на исходный уровень. Площадь 0 сама по себе не означает Not Placed: состояние определяется отсутствием Location.
- Для размещённого Room сохраняются исходная фаза и X/Y точки. Новая запись создаётся в исходной фазе, размещается через PlanCircuit целевого уровня, затем её точка переносится на исходные X/Y. Для такого размещения нужен план целевого уровня и доступная топология в исходной фазе; при отсутствии подходящих данных операция завершается ошибкой без удаления исходника. Контуры, стены и Room Separation Lines отдельно не создаются и не перемещаются.
- Нижняя привязка становится целевым уровнем; Base Offset компенсирует разницу ProjectElevation. Если Upper Limit указывал на исходный уровень, он также заменяется с компенсацией Limit Offset; другая верхняя привязка сохраняется. Сохраняются абсолютные отметки низа/верха. Площадь, объём и другие вычисляемые readonly-значения рассчитывает Revit по новой привязке и границам; буквальное совпадение площадей не гарантируется.
- Для Not Placed создаётся новая неразмещённая запись в исходной фазе через NewRoom(Phase), переносятся значения, исходная запись удаляется. Это сохраняет требуемое состояние без промежуточного размещения/Unplace и без назначения произвольной точки. У новой записи нет нижней привязки к удаляемому уровню; числовые смещения сохраняются без компенсации, поскольку размещения нет. Если задана верхняя ссылка на исходный уровень, она заменяется целевым.
- Переносятся все заданные доступные для записи параметры экземпляра по ID параметра внутри документа, включая имя, номер, рабочий набор, проектные и общие параметры. Фаза задаётся при создании, уровни и смещения обрабатываются отдельно. Незаданные и readonly-параметры не записываются. Ошибка переноса любого заданного writable-параметра отменяет замену. Служебные ID/UniqueId меняются; внешние ссылки на старый ID автоматически не переназначаются.
- Первый вариант исключает закреплённые помещения, группы, сборки, варианты конструкции и неподдержанные зависимости. Вопрос переноса марок требует отдельного решения; до его согласования помещения с RoomTag не пересоздаются. Допускаются служебные зависимые DB.Element без категории. Снимки и сравнения результатов в рабочую операцию не добавляются; границы, значения, зависимости и Undo проверяются отдельно на копии модели.

# Вкладка «Виды»



- Показываются нешаблонные виды, у которых связанный уровень (`GenLevel`) совпадает с исходным.
- Колонки: отметка, ID, имя, тип вида и статус.
- Статус всегда начинается с «Поддерживается» или «Не поддерживается» (на выбранном языке интерфейса). Это поддержка пересоздания вида; далее указывается причина ограничения и, при наличии, результат последней операции. Результат операции не заменяет признак поддержки.
- «Открыть виды» последовательно открывает отмеченные виды; последний успешно открытый становится активным. Ошибки выводятся по ID.
- «Удалить виды» использует правила удаления ниже. Зависимые виды и виды с зависимыми видами удалять нельзя.
- «Пересоздать виды» открывает диалог префикса имени и подтверждения цели; в старом окне цель выбирается в этом диалоге, в новом берётся из Transfer.

# Пересоздание видов

## Поддержка и результат

- Поддерживаются планы этажей (`FloorPlan`), потолков (`CeilingPlan`) и конструкций (`EngineeringPlan`).
- Не поддерживаются планы площадей, шаблоны, зависимые виды, виды с зависимыми видами и остальные типы.
- Новый вид имеет тот же тип и выбранный целевой уровень.
- Имя нового вида: префикс + исходное имя. При занятом или недопустимом имени вид не создаётся; обработка остальных продолжается.
- Команда не удаляет исходные виды и их размещения на листах. Новые виды размещаются на тех же листах поверх исходных: сохраняются центр видового экрана, его тип, поворот, смещение подписи, длина линии подписи и закрепление. Номер нового видового экрана назначает Revit; номер оригинала не изменяется. Если исходный вид не размещён, новый также остаётся без размещения.
- Размещение выполняется после копирования настроек и содержимого, отдельной транзакцией для каждого исходного видового экрана внутри общего Undo. Ошибка размещения откатывает только эту попытку; созданный вид и ранее завершённые этапы сохраняются. Журнал содержит причину отказа или ID листа и обоих размещений при успехе. Критический сбой отменяет весь пакет по общей политике.
- Новый вид сохраняется до переноса настроек и содержимого. Ошибка последующего этапа не должна лишать пользователя уже созданного результата.
- Частично заполненный и пустой новый вид сохраняется для осмотра. Журнал явно перечисляет потери и непроверенные результаты.
- Все изменения одного запуска пересоздания отменяются одним действием Undo.

## Настройки вида

- Сохраняются масштаб, ориентация, применимые настройки отображения, графика категорий, фильтры и их порядок.
- Назначается исходный шаблон. Автоматически назначенный при создании шаблон не должен мешать переносу настроек.
- Сохраняются фаза, уровни подложки и заголовок на листе, включая пустой заголовок.
- Секущий диапазон копируется с теми же значениями уровней и смещений, без пересчёта абсолютной высоты плоскостей.
- Правило диапазона и подложки не гарантирует удаления всех ссылок на исходный уровень или одинакового видимого сечения модели. Этот вопрос отдельно отмечен в TASKS.md.
- Используется исходный Scope Box. При его наличии форма обрезки не задаётся независимо от него.
- Без Scope Box сохраняются прямоугольная или непрямоугольная обрезка и её границы в плане.
- Сохраняются активность и видимость обрезки, а также доступные настройки обрезки аннотаций. Выключенная обрезка не является причиной терять её сохранённые границы.
- Если ориентацию или форму обрезки сохранить невозможно, журнал сообщает об отличии.
- Разделённая обрезка не поддерживается: этап настроек отклоняется, созданный вид сохраняется.

## Аннотации, детализация и графика

- Переносятся тексты, марки, размеры, высотные отметки, линии детализации и заполненные области.
- Сохраняются положение на виде, содержимое, применимые выноски и ссылки на правильные объекты модели.
- Отсутствие габаритов у высотной отметки само по себе не является основанием для пропуска.
- Модельные элементы не копируются. Неподдерживаемые элементы содержимого пропускаются с исходным ID и причиной.
- Группы аннотаций и отдельное копирование настроек инсоляции пока не поддерживаются.
- Сохраняются индивидуальные переопределения графики и постоянное скрытие модельных элементов, скопированных аннотаций и детализации.
- Отсутствие переопределений или скрытия у исходника тоже должно сохраняться.
- Неоднозначное сопоставление копии с исходником → копию сохранить; графику не назначать наугад; записать ID кандидатов.
- Ошибка оформления одной копии не отменяет саму копию и не мешает остальным.
- Наличие копии не доказывает правильность её текста, значения или ссылок. Непроверенные автоматически результаты явно помечаются для ручной проверки.

## Ошибки и журнал

- Предупреждения Revit записываются с исходным текстом, кодом и ID. Допустимые предупреждения могут быть сняты для сохранения результата.
- Ошибка, запрещающая фиксацию, отменяет текущий этап. Остальные этапы и виды продолжают обрабатываться, если состояние документа позволяет.
- Отличия настроек и графики отражаются в журнале; новый вид сохраняется.
- При изменении или удалении существующих объектов записываются конкретные ID. По принятой политике результат сохраняется для проверки пользователем и может быть отменён через Undo.
- Обновления известных служебных объектов отслеживания можно показывать как информацию; неизвестные изменения и любые удаления остаются предупреждениями.
- Критический сбой отменяет весь пакет. Сводка показывает ноль созданных видов; недействительные ID нельзя использовать для открытия.
- Журнал открывается в отдельном изменяемом по размеру окне.
- Сводка показывает созданные и несозданные виды, замечания и ошибки. Созданный вид с потерями не должен выглядеть как полностью проверенный результат.
- Запись содержит этап, уровень сообщения, ID исходного и нового вида, ID проблемного элемента, описание, рекомендацию и технические подробности.
- Действия: поиск по тексту/ID; фильтр замечаний/ошибок; копирование записи или всего журнала; открытие нового вида.
- Сохранение выполняется только по кнопке: полный журнал независимо от фильтра, UTF-8 `.txt`.

# Удаление элементов и видов, отмена

- Удаление доступно для отмеченных видимых строк соответствующей вкладки. Перед удалением определяется полный состав удаляемого объекта и зависимостей в пробной операции с откатом.
- Пользователь подтверждает состав удаления; действие по умолчанию — отмена.
- Уровни нельзя удалить прямо или через зависимости. Удаление вида допускает его содержимое и размещения на листах, но не другие виды.
- При удалении элемента допускаются подтверждённые зависимости, но не уровни и не виды. Операции с видами выполняются только на вкладке «Виды».
- Фактический состав должен совпасть с подтверждённым. Неожиданные изменения, предупреждение Revit или ошибка приводят к откату попытки.
- Закрытие окна не отменяет завершённые операции. Для отмены используется Undo Revit.

# Проверка перед использованием на проектах

- Проверены все три типа планов, настройки, обрезка, аннотации, ссылки, частичный результат и общий Undo.
- Проверены таблицы, поиск, фильтрация, выбор уровня и язык; случаи 1 и 2 переноса элементов и Undo, отдельно нижняя, верхняя и обе привязки; удаление элементов и видов с зависимостями, отмена подтверждения и защита уровней.
- Проверки выполнены на копиях двух проектов компании. В TASKS.md указаны версии Revit, фактические результаты и оставшиеся ограничения.
- Нельзя объявлять уровень безопасным для удаления только по пустой таблице или числу пересозданных видов. Исходные виды и оставшиеся связи требуют отдельной проверки пользователем.
