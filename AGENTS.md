# Инструкции по разработке ReLevel

## Проект

ReLevel — плагин для работы с элементами и видами уровней в Autodesk Revit 2025.

Реализованы выбор элементов по уровню или исходному выделению, выделение и удаление элементов, перенос поддерживаемых элементов на другой уровень с сохранением положения и геометрии. Для видов уровня доступны открытие и удаление.

Пересоздание видов пока не реализовано: кнопка недоступна. Поиск и фильтр таблиц пока представлены только интерфейсом. Не описывай эти функции как работающие и не реализуй их без отдельной задачи.

## Целевая среда

- Autodesk Revit 2025
- C#
- .NET 8
- Revit API 2025
- Visual Studio 2022
- VS Code
- Windows

## Архитектура

Один проект `src/ReLevel.Revit/ReLevel.Revit.csproj`, одна сборка плагина `ReLevel.Revit.dll`. Отдельные проекты Core и unit-тестов не используются. Не добавляй unit-тесты и инфраструктуру для них.

Разделяй ответственности внутри проекта:

- `Logic/` — расчёты смещений, координаты и результаты операций без зависимостей от Revit API;
- `Transfer/` — анализ, стратегии переноса, транзакции и проверки геометрии;
- `UI/` — WPF-интерфейс;
- `ReLevelCommand.cs` — вход в команду;
- `DeleteService.cs` — проверка зависимостей и транзакционное удаление.

Revit API предоставляется установленным Revit и не копируется в комплект плагина. Манифест `ReLevel.addin` находится в корне репозитория.

## Архитектура переноса элементов

Не следует считать, что все элементы Revit можно переносить между уровнями путём изменения одинаковых параметров.

Разные типы элементов Revit могут использовать разные механизмы привязки к уровню и позиционирования.

Поэтому специфичное для разных элементов поведение должно быть изолировано с помощью стратегий переноса или другой эквивалентной абстракции.

Предпочтительно группировать элементы по механизму переноса, а не создавать отдельную реализацию для каждой категории без необходимости.

Не создавай отдельную стратегию для каждой категории Revit, если их поведение при переносе фактически одинаково.

## Сохранение положения

Основной инвариант ReLevel:

`ModelPositionBefore == ModelPositionAfter`

с учётом допустимой численной погрешности.

Изменение привязанного уровня разрешено.

Непреднамеренное изменение положения или геометрии элемента запрещено.

Для соответствующих элементов также могут быть важны следующие инварианты:

- размеры элемента не изменились;
- конечные точки кривых не изменились;
- координаты MEP-коннекторов не изменились;
- связь с хостом осталась корректной;
- системные соединения остались корректными.

Точные требования к проверке могут различаться для разных типов элементов.

Конкретные алгоритмы переноса описываются в `Categories.md`, и на их основе реализуется код. Перед изменением стратегии прочитай соответствующий раздел. При добавлении или изменении механизма укажи параметры, условия применимости, ограничения, проверки сохранения состояния и основания для отката; поддерживай документ и код согласованными.

Расчёт смещения выполняется во внутренних единицах Revit с использованием `Level.ProjectElevation`: новое смещение = старое смещение + отметка исходного уровня − отметка целевого уровня.

Отказ от unit-тестов не отменяет проверки состояния во время выполнения: проверяй уровень, смещение, положение и геометрию после регенерации и фиксации транзакции. При нарушениях выполняй откат.

## Перенос видов

Правила и алгоритмы переноса или пересоздания видов описываются в [Views.md](Views.md). Перед работой над этими функциями прочитай соответствующий раздел и реализуй код на основе описанного поведения.

В документе фиксируются условия применимости, переносимые настройки и содержимое вида, работа с зависимостями, судьба исходных видов, проверки результата и основания для отката. Поддерживай документ и код согласованными, явно отличая запланированное поведение от реализованного. Если нужный алгоритм ещё не описан или требования неоднозначны, уточни их у пользователя.

`Categories.md` описывает перенос элементов, `Views.md` — перенос видов. Наличие описания в документе само по себе не является поручением реализовать функцию.

## Неподдерживаемые элементы

Никогда не изменяй элемент с помощью непроверенного универсального способа.

Если ReLevel не знает, как безопасно перенести элемент:

- пометь его как неподдерживаемый;
- не изменяй его;
- сообщи вызывающему коду или пользователю причину.

Частичная, но надёжная поддержка предпочтительнее небезопасной универсальной реализации.

## Транзакции

Все изменения документа Revit должны выполняться внутри корректных транзакций Revit.

Избегай неоправданно больших областей транзакций.

Ошибки переноса должны обрабатываться явно.

Ошибка при обработке одного элемента не должна повреждать или некорректно изменять другие элементы.

## Качество кода

Предпочтительно:

- небольшие классы с одной понятной ответственностью;
- явные и понятные имена;
- простой поток выполнения;
- понятные расчёты, отделённые от операций с документом;
- разделение расчётов, Revit API и интерфейса внутри одного проекта.

Избегай:

- ненужных абстракций;
- архитектуры «на будущее» без текущей необходимости;
- больших классов с несвязанными обязанностями;
- дублирования расчётов переноса;
- зависимостей Revit API в простых расчётах из `Logic/`;
- молчаливого подавления исключений.

Не рефактори несвязанный рабочий код, если текущая задача этого не требует.

## Процесс разработки

Работай небольшими последовательными этапами.

Для каждой задачи:

1. Прочитай `AGENTS.md`.
2. Прочитай `docs/SPEC.md`.
   Для задач переноса элементов также прочитай `Categories.md`, для переноса или пересоздания видов — `Views.md`.
3. Перед изменениями изучи существующую реализацию.
4. Реализуй только запрошенный объём задачи.
5. По возможности собери затронутые проекты.
6. Сообщи, что было изменено.
7. Сообщи, что фактически было проверено.
8. Явно сообщи обо всём, что проверить не удалось.

Не утверждай, что поведение внутри Revit проверено, если оно фактически не тестировалось в Revit.

Основная автоматическая проверка — `dotnet build ReLevel.sln -c Release`. Поведение проверяется вручную в Revit на копии модели: перенос, сохранение координат и геометрии, пропуск неподдерживаемых элементов, удаление с зависимостями и откат. Успешная сборка не заменяет эти проверки.

Удаление элементов и видов требует подтверждения пользователем в интерфейсе плагина. Уровни запрещено удалять напрямую или через зависимости. Сохраняй существующие проверки состава удаления и откат при побочных изменениях.

## Контроль области задачи

Не реализуй будущие функции только потому, что они упоминаются в спецификации.

Спецификация описывает предполагаемый конечный продукт.

Текущая задача, поставленная пользователем Codex, определяет, что необходимо реализовать сейчас.

Если требования неоднозначны и эта неоднозначность может существенно повлиять на архитектуру или поведение в Revit, остановись и объясни проблему вместо самостоятельного придумывания требования.
