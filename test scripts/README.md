## Восемь оставшихся Area Boundary на LEVEL 0

Сохраняемый вариант после успешной пробы: `transfer_area_boundaries.py`. Запуск на копии модели, цель Level LL / 1518530. Использует те же соседние модули и алгоритм пересоздания, но после успешного Commit/сбора данных оставляет результат через TransactionGroup.Assimilate. Старые восемь линий заменяются новыми; созданные два плана площадей тоже остаются. Уровень скрипт не удаляет. Один Undo отменяет всю замену с планами; если после неё удаляли уровень, сначала отмените удаление отдельным Undo. Отчёт `area_boundary_transfer_*.json`, успех — `kept=true`, `group_assimilate=Committed`. Ошибка до фиксации группы откатывает операцию.

После отказа смены SketchPlane запустите `probe_recreate_area_boundaries.py`. Он использует соседние `probe_area_boundary_levels.py`, `recreate_room_separator.py` и `change_room_separator_plane.py` (только функции, без запуска их операций). Выберите Level LL / 1518530: проба требует совпадающей отметки, сохраняет XYZ, определяет схемы через зависимости AreaScheme, использует или временно создаёт планы площадей целевого уровня. Создаёт замену каждой линии, копирует writable-параметры и удаляет исходники внутри откатываемой группы. Даже успешный Commit отменяется, включая новые планы и удаление исходников. Отчёт `reports/area_boundary_recreate_*.json` содержит соответствие старых/новых ID, схемы, параметры, состав удаления, геометрию линий и площади до/после. Отказ этой пробы не запускает постоянное удаление.

Запустите `probe_area_boundary_levels.py` целиком в RevitPythonShell на копии модели. Рядом должен находиться `change_room_separator_plane.py`: используются только его функции чтения и обработки ошибок, его операция не запускается. Проба читает 2774087–2774093 и 3545837 напрямую по ID, предлагает целевой уровень по ID или имени (по умолчанию Level LL, 1518530), затем пробует назначить линиям SketchPlane от целевого уровня. Сами линии, площади, планы и уровни не удаляются. Любое предупреждение/ошибка отклоняет Commit; даже успешная транзакция полностью отменяется внешней группой.

Отчёт `reports/area_boundary_probe_*.json` содержит линии до/после (ID, LevelId, плоскость, концы/длина, зависимости), Area на исходном/целевом уровне (схема, площадь и ID границ), ошибки, последний обрабатываемый ID и статус отката. Ожидается `group_rollback=RolledBack`, если группа запускалась. Проверяется только прямая перепривязка; отказ ещё не доказывает невозможность пересоздания. Отправьте JSON для выбора следующего шага. Успешная компиляция плагина не проверяет Python или поведение API в этой пробе.

`inspect_transfer_failures.py` содержит все 86 ID из таблицы ошибок. Запуск: RevitPythonShell в Revit 2025+ на копии того же проекта. После обновления DLL перезапустите Revit, один раз откройте и закройте ReLevel, затем выполните скрипт целиком. Скрипт использует именно загруженный плагин; его путь и ModuleVersionId записываются в отчёт. Новая DLL находится в `bin/2025+/ReLevel/ReLevel.Revit.dll`.

Сначала собираются классы, категории, параметры, соединения, зависимости и существующие предупреждения. Далее введите исходный и целевой уровни из неудачного переноса — ID или точные имена. Cancel оставляет только сбор данных без изменений. Для пробы вызывается текущий алгоритм ReLevel по всем ID в порядке таблицы; успешные переносы сохраняются до конца пробы, затем **весь пакет откатывается**, включая Unjoin. Скрипт ещё не запускался в RevitPythonShell.

`inspect_areas.py` запускается целиком через RevitPythonShell в открытом проекте Revit 2025. Выделять Area и искать вид не требуется. Скрипт только читает модель, транзакций нет.

# Проба пересоздания Room Separator

`recreate_room_separator.py` проверяет замену линии `22043147` новой Room Separation Line с переносом доступных параметров. Запускается целиком в RevitPythonShell; рядом должен находиться `change_room_separator_plane.py` (общие функции, прежняя проба при импорте не запускается).

- Введите ID или точное имя целевого уровня, например `30` / `LEVEL 0` для текущего проекта. Эта первая проба допускает только совпадающие отметки уровней и сохраняет XYZ. Нужен существующий план этажа целевого уровня с фазой исходной линии; если его нет, скрипт объяснит причину остановки.
- Новая линия получает рабочий набор, фазы и остальные доступные для записи заданные параметры исходника. Вычисляемые/readonly значения только читаются. Несовпадения попадают в отчёт.
- Оригинал временно удаляется, чтобы собрать реальный состав удаления. **Вся проба всегда откатывается**, даже при успешном Commit: после запуска в модели остаётся исходная линия. Поэтому эта версия предназначена для отчёта, а не визуального осмотра сохранённой замены.
- Отчёт `reports/room_recreate_22043147_*.json`: `parameter_copy`, `parameters_before/after`, `parameter_differences`, `deleted_elements`, `failures`, `group_rollback`. При нормальном завершении группы последнее поле должно быть `RolledBack`.

По первому отчёту создание и запись параметров прошли, но Commit откатился из-за предупреждений о пересечении разделителя со стенами. Обновлённая проба сохраняет в `failures` и снимает только это предупреждение (GUID `f7b3a015-c3eb-4a3f-b345-c474ec07d43f`), чтобы прочитать результат после Commit. Другие предупреждения и ошибки приводят к откату транзакции. Успешный Commit всё равно отменяется внешней группой; снятие предупреждения не исправляет наложение и не доказывает правильность границ помещений.

Пересоздание включено в плагин как Кейс 8 для прямых линий между уровнями на совпадающих отметках. C#-реализацию ещё требуется проверить в Revit; проба остаётся отдельным инструментом сравнения параметров и зависимостей. Новый ID и новый SketchPlane отличаются от исходных.

Отчёт 01.10.2026 `173101_8e03c467` подтвердил успешный Commit для 22043147 → LEVEL 0 в Revit 2025 build 25.4.41.14: четыре доступных параметра совпали, LevelId новой линии равен 30. Единственное различие снятых параметров — вычисляемая длина примерно на 0.000002432 mm. Группа затем успешно откатилась. Сохранность границ помещений и результат удаления исходного уровня этим отчётом не проверены.

# Проба рабочей плоскости Room Separator

`change_room_separator_plane.py` запускается целиком через RevitPythonShell в Revit 2025 на копии модели. Он работает строго с ID `22043147`, независимо от выделения.

1. Откройте скрипт в редакторе RevitPythonShell и выполните его.
2. Введите ID целевого уровня или его точное имя. Список уровней выводится в консоль. Cancel отменяет изменение.
3. Скрипт создаёт SketchPlane на целевом уровне и назначает его существующей линии через `line.SketchPlane`. Уровни, старая плоскость и линия не удаляются; геометрия кривой отдельно не записывается. При разных отметках уровней линия может переместиться по высоте — это часть проверяемого поведения.
4. Успешный Commit **остаётся в модели**, его можно отменить одним Undo. При предупреждении/ошибке Revit транзакция откатывается, автоматические исправления не применяются.
5. Проверьте положение линии, границы/площади помещений и на копии модели — сохранится ли линия после удаления исходного уровня. Сам скрипт уровень не удаляет. Если проверяли удаление, сначала отмените его отдельным Undo.

Отчёт `reports/room_plane_22043147_*.json` содержит плоскость, LevelId, координаты, длину и зависимости до/после, статус транзакции и сообщения Revit. Если после успешного Commit не удалось прочитать снимок или записать файл, это само по себе не отменяет изменение; смотрите статус/сообщения консоли. При отсутствии `__file__` используется `PROJECT_SCRIPT_DIR`. Запуск нового скрипта в Revit ещё не проверен.

Результат пробы Room Separator от 01.10.2026: Revit 2025 build 25.4.41.14 запретил назначение SketchPlane линии 22043147 (`Changing the SketchPlane of this CurveElem is not allowed`). Скрипт сохранён как воспроизводимая проба этого ограничения.

# Проба внутренних стен Swept Wall Void

`probe_void_wall_levels.py` запускается целиком через редактор RevitPythonShell в Revit 2025 **на копии модели**. Выделение не нужно. Скрипт проверяет ID/UniqueId стен 21941510 и 22051705, предлагает целевой уровень по ID или точному имени. Исходный низ обеих стен должен быть LEVEL 0 (30). Cancel выходит без изменения модели.

В одной транзакции меняется только Base Constraint каждой стены и Base Offset с компенсацией разницы ProjectElevation. Верхние привязки не записываются. Внешние стены и семейства не перемещаются кодом. Ошибки и предупреждения откатывают транзакцию; Unjoin и удаление размеров не выполняются. Даже успешный Commit находится внутри TransactionGroup, которая **обязательно откатывается после чтения результата**. Ничего не остаётся в модели, Undo для этой пробы не требуется. При сбое регенерации дальнейшее чтение прекращается. Если откат не подтверждён, сообщение и отчёт явно показывают ошибку; следует прекратить работу и проверить Revit.

Наблюдаются 22 известных ID двух групп и внешних стен, их непосредственные зависимости и соединённые со стенами элементы. До и после Commit снимаются Location, габариты, объёмы/площади/число граней и рёбер тел, доступные кривые, уровни/смещения и ID зависимостей. Для Family читаются IsInPlace и FamilyPlacementType. DocumentChanged фиксирует изменённые, созданные и удалённые ID всей транзакции; для изменённых объектов вне наблюдаемого набора снимка «до» нет — они перечислены отдельно. Изменение ID в событии не доказывает перемещение. Отсутствие различий в сводных величинах не доказывает тождество всей формы и ссылок.

Отчёт `reports/void_wall_probe_*.json` содержит before/after/differences, ошибки Revit, commit_status и group_rollback. Ожидаемый итог отката — `RolledBack`. Путь выводится после `Report:`; пришлите JSON для анализа. Из-за автоматического отката смотреть результат нужно по отчёту, а не по оставшемуся состоянию модели. Скрипт в Revit пока не запускался.
# Сохраняемый перенос внутренних стен для проверки удаления уровня

После откатываемых проб используйте **`transfer_void_wall_levels.py`** на копии модели через RevitPythonShell. Он переносит нижние привязки только 21941510 и 22051705 с компенсацией смещений и оставляет успешный результат в модели. Исходный уровень обеих стен должен быть LEVEL 0 (30); ID/UniqueId проверяются. В запросе по умолчанию стоит `1519130` (Level 1). Cancel ничего не меняет.

Порядок записи и диагностические снимки такие же, как у probe_void_wall_levels.py. Отличие: после успешного Commit и чтения снимков группа фиксируется через Assimilate. В консоли должно появиться `TRANSFER KEPT`, в JSON — `kept=true`, `group_assimilate=Committed`. Если транзакция не зафиксирована или выполнение прервалось до Assimilate, группа откатывается. Ошибки/предупреждения не подавляются, размеры не удаляются. Если после Assimilate не удалось записать JSON, перенос всё равно остаётся; проверяйте строку TRANSFER KEPT и отменяйте через Undo при необходимости.

Затем вручную запустите удаление LEVEL 0 и проверьте, исчезли ли две группы Swept Wall Void из состава удаления. Скрипт уровни не удаляет. После фактического удаления сначала отмените удаление отдельным Undo; ещё один Undo отменит перенос обеих стен. В отменённом диалоге удаления отдельного Undo нет. Пришлите отчёт `reports/void_wall_transfer_*.json` и оставшийся список ID из проверки удаления. Этот сохраняемый вариант ещё не проверен в Revit; откатываемый алгоритм ранее прошёл две пробы.
