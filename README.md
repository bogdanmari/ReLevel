# ReLevel

Плагин Autodesk Revit 2025, .NET 8, Windows x64. Работа с элементами уровня или исходным выделением и видами уровня. Перенос сохраняет положение через замену привязок и компенсацию смещений, проверяет геометрию, хосты и MEP-соединения. **Расширенные механизмы скомпилированы, но ещё не проверены на моделях в Revit.**

## Сборка и установка

**Готовые файлы всегда находятся в корневой папке `bin`. Вариантов только два.**

| Что собрать | Конфигурация в IDE | Папка результата |
| --- | --- | --- |
| Основная версия `2025+` | Release (или Debug) | `bin/2025+/` |
| Старая версия `2024-` | Legacy | `bin/2024-/` |

Обычный **Build** с Debug/Release обновляет только `2025+`. Для старой версии выберите **Legacy → Build**. Обе конфигурации создают одинаковую структуру:

```text
bin/
  2025+/
    ReLevel.addin
    ReLevel/ReLevel.Revit.dll
  2024-/
    ReLevel.addin
    ReLevel/ReLevel.Revit.dll
```

Дополнительные PDB/deps-файлы — результаты компиляции. Debug и Release используют одну папку `2025+`: в ней находится последний собранный вариант.

Из командной строки:

```powershell
dotnet build ReLevel.sln -c Release
dotnet build ReLevel.sln -c Legacy
```

Исходники основной версии — `src/ReLevel.Revit`. В `legacy/src/ReLevel.Revit` находится последняя адаптация для старых Revit (2026-09-25). Обновляем её из основной версии **только по прямому запросу пользователя**. Сборка Legacy компилирует уже адаптированные исходники и сама их не синхронизирует. Проект, решение, манифест и документация общие.

Для компиляции нужны SDK .NET 8 или новее, API Revit 2025 для основной версии, API Revit 2022 и .NET Framework 4.8 Developer Pack для Legacy. API по умолчанию берётся из установленного Revit соответствующего базового года; другой каталог задаётся через `-p:RevitInstallDir=...`. Выбирать каждый год не нужно. Старый параметр `RevitVersion` больше не используется.

Версия `2025+` собирается один раз на .NET 8 против API 2025 и предназначена для 2025/2026; `2024-` — один раз на .NET Framework 4.8 против API 2022 и предназначена для 2022–2024. Названия обозначают две линейки, а не обещание поддержки любых будущих или более старых Revit. В Legacy доступ к ID и встроенным параметрам адаптируется к API запущенного Revit, включая 64-битные значения 2024. Это необходимо из-за [изменений бинарной совместимости API 2024](https://blog.autodesk.io/64-bit-element-ids-maybe/).

**Проверено 2026-09-29:** основная сборка Release проходит с API Revit 2025, без ошибок и предупреждений; DLL обновлена в `bin/2025+/ReLevel`. Ранее проверялись сборка Legacy и инициализация её адаптеров с API 2022/2024 вне Revit; текущие изменения в Legacy не переносились. Проверка с API 2023 вне Revit не завершилась из-за отсутствующих зависимостей. **Запуск новой команды и операции в моделях пока не проверены**, в том числе загрузка основной DLL в Revit 2026. Компиляция основной версии не использует API установленного Revit 2026.5 и не требует для него отдельной сборки.

Установка при закрытом Revit: скопируйте содержимое подходящей папки `bin/2025+` или `bin/2024-` в `%APPDATA%\Autodesk\Revit\Addins\<год>`. В каталоге года должны оказаться `ReLevel.addin` и папка `ReLevel` с DLL. Для каждого года одной линейки используется одна и та же DLL. Библиотеки Autodesk в комплект не копируются. Команда: **Надстройки → Внешние инструменты → ReLevel**.

## Интерфейс

В основной версии `2025+` при первом запуске язык выбирается по интерфейсу Revit: русский → **Русский**, английский и остальные языки → **English**. Переключатель **English / Русский** находится справа сверху; ввод текста в нём отключён. Он меняет интерфейс сразу и задаёт язык последующих диалогов и результатов. Ручной выбор сохраняется до завершения сеанса Revit, в том числе при повторном открытии команды. Имена из модели и сообщения самого Revit сохраняют исходный язык; уже сформированные результаты операций не переписываются. Версия `2024-` остаётся без этих изменений.

Окно открывается по центру экрана с начальным размером 920 × 607,2 единицы WPF. Кнопки под таблицами расположены справа. Чек-бокс в заголовке отмечает все строки или снимает отметки; частичная отметка показана промежуточным состоянием. Если выделить несколько строк через Ctrl/Shift и нажать галочку одной из них, новое состояние применяется ко всему выделению. Пробел на чек-боксе работает так же.

Верхняя строка: «Уровень» и «Работать с выбранными элементами». Выделение запоминается при запуске команды. Без него переключатель недоступен. При включении список уровней очищается и блокируется, вкладка «Виды» недоступна. При выключении нужно снова выбрать уровень. Смена режима/уровня сбрасывает отметки и результаты строк.

**Элементы:** отметка, ID, категория, `Element.Name`, статус/причина; в режиме выделения дополнительно уровень (или несколько обнаруженных связей). Отмеченные строки можно выделить в Revit, удалить после подтверждения или перенести через диалог целевого уровня. Отметка отличается от обычного выделения строки таблицы. Кнопки неактивны без отметок. Результаты выводятся по ID, включая объекты, исчезнувшие из таблицы после операции. Перенесённые, пропущенные и ошибки подсчитываются отдельно.

**Виды:** нешаблонные виды с `GenLevel`, равным выбранному уровню; отметка, ID, имя, тип вида и статус. Статус всегда начинается с «Поддерживается» / «Не поддерживается» и относится к пересозданию. Далее показаны причина ограничения и результат последней операции, если он есть. Отмеченные виды можно последовательно открыть (последний становится активным) или удалить после подтверждения. «Пересоздать виды» создаёт планы этажей, потолков и конструкций на другом уровне с префиксом имени, настройками, шаблоном, секущим диапазоном и аннотациями. Исходные виды и их размещения на листах сохраняются; новые виды на листы не размещаются. Требования: [SPEC — пересоздание видов](docs/SPEC.md#пересоздание-видов); фактическое состояние и проверки: [Tasks](Tasks.md).

Поиск в обеих таблицах работает по видимым колонкам без учёта регистра. Стрелки и Enter/Shift+Enter переходят между совпавшими строками, «Фильтр» оставляет только совпадения. Пустой запрос показывает все строки. Общая отметка и операции применяются только к видимым строкам; скрытые отметки сохраняются до обновления данных, но не участвуют в операциях.

В выпадающих списках исходного и целевого уровней можно вводить часть имени: остаются только совпадения без учёта регистра, отсортированные по имени. Очистка текста показывает все варианты. Выберите уровень мышью или клавиатурой; Enter в раскрытом списке подтверждает выбор, но не запускает перенос. При ручной проверке проверьте также отсутствие совпадений, повторное открытие списка и переключение режима выбранных элементов.

Состояние существует только в памяти окна. Закрытие окна не отменяет выполненные операции; отмена — через Undo Revit. История автоматически не записывается в файлы или параметры проекта. Журнал пересоздания видов можно явно сохранить в `.txt`.

Пересоздание сохраняет новый вид до копирования настроек и содержимого. Ошибки последующих этапов и диагностические замечания показываются в отдельном журнале и обычно не отменяют вид. В журнале доступны исходные ID проблемных элементов, подробности Revit, поиск, копирование, сохранение и открытие нового вида. Ошибка самого создания или критический сбой Revit всё ещё могут помешать сохранению результата.

## Категории и условия переноса

Это перечень реализованных механизмов основной версии, а не подтверждение работы каждого семейства на реальном проекте. Категория сама по себе не разрешает перенос: учитываются способ размещения, доступные параметры, хост и зависимости. Для точечных семейств нет закрытого списка категорий; названия ниже помогают подобрать случаи для проверки в проекте.

Для обычных элементов и проверяемых соседей требуется доступная твёрдотельная геометрия. Семейства только с условным обозначением или сеткой могут быть отклонены, даже если их категория есть в таблице. Для проёмов проверяется контур, для систем — состав участников. Смена порядка тесселяции также может вызвать консервативный откат и требует разбора конкретного примера.

| Категории / объекты | Реализованный механизм и условия |
| --- | --- |
| Мебель, мебельные системы, оборудование, обобщённые модели, шкафы, специальные устройства | Точечные одноуровневые загружаемые семейства с доступной парой уровня и смещения |
| Озеленение, антураж, парковка, загружаемые компоненты участка | Тот же механизм; системные объекты рельефа в него не входят |
| Сантехнические приборы, механическое оборудование | Точечные семейства; дополнительно проверяются применимые коннекторы, соседи и системы |
| Электрооборудование, электрические и осветительные приборы, устройства освещения | Точечные семейства, включая размещённые на хосте при самостоятельной доступной привязке; проверяются цепи и коннекторы |
| Устройства связи, передачи данных, телефонии, охраны, пожарной сигнализации, вызова персонала, аудиовизуальные устройства | Тот же механизм семейств; конкретный экземпляр должен иметь подходящее размещение и параметры |
| Воздухораспределители, спринклеры | Точечные семейства с проверкой подключений; зависимость от потолка/грани сохраняется |
| Соединительные детали и арматура труб/воздуховодов; соединительные детали лотков/коробов | Точечные семейства с собственной записываемой привязкой; производная привязка без доступного уровня пропускается |
| Двери, окна, семейства на стене/перекрытии/потолке/грани/рабочей плоскости | При доступной самостоятельной привязке переносится она. Иначе экземпляр проверяется как зависимость при переносе хоста; перепривязки к другому хосту нет |
| Стены | Прямые вертикальные базовые стены без изменённого профиля и присоединения: низ, верх или обе привязки к источнику. Вставки, проёмы и известные соединения проверяются вместе со стеной |
| Перекрытия, плоские фундаментные плиты класса Floor, потолки | Горизонтальные плоские хосты без редактирования формы, с проверкой отверстий, размещённых семейств и соединений |
| Архитектурные и несущие колонны | Вертикальные двухуровневые загружаемые колонны без присоединения: низ, верх или обе привязки |
| Отдельные фундаменты и другие загружаемые несущие компоненты | Только при точечном одноуровневом размещении с доступной привязкой; системные ленточные фундаменты и балки этим механизмом не охватываются |
| Трубы, воздуховоды, кабельные лотки, короба | Прямые участки, включая наклонные, с известной привязкой и проверкой обоих концов, уклона, соединений и систем |

В режиме уровня изменяются только поддерживаемые привязки к выбранному источнику. Например, у стены с источником только сверху меняются верхний уровень и верхнее смещение, низ остаётся прежним. В режиме выделения несколько обнаруженных уровней дают пропуск с объяснением; для такого объекта используйте режим уровня.

Зависимые вставки, вложенные компоненты, соединённые соседи и системы включаются в заранее определённую проверку, их количество показывается в статусе. Они не становятся дополнительным выделением для переноса. Для зависимых семейств разрешены только проверенные производные изменения привязки от хоста с неизменной геометрией; самостоятельные уровни соседних элементов не переписываются. Ошибка проверки откатывает попытку целиком. Поддержка сложного случая определяется результатом проверки конкретного экземпляра.

## Ограничения

- Поиск `LevelRelationFinder` учитывает известные нижние, верхние и опорные привязки, хосты и рабочие плоскости. Основание связи показано в статусе; уровень не угадывается по высоте или имени. Неизвестные зависимости и уровни связанных RVT не сопоставляются с локальными уровнями. В режиме выделения показываются существующие элементы исходного выделения без фильтра по уровню.
- Не реализованы перенос крыш, лестниц, пандусов, ограждений, системного рельефа, балок/раскосов, гибких и криволинейных MEP-трасс, In-Place, составных/витражных/наклонных/профилированных и присоединённых стен, наклонных/присоединённых колонн. Вложенные компоненты самостоятельно не переносятся. Закрепление, группы, сборки и варианты конструкции остаются защитными ограничениями. Производные или недоступные привязки не обходятся принудительным перемещением. Требования: [SPEC — перенос элементов](docs/SPEC.md#перенос-элементов); результаты и ручные проверки: [Tasks](Tasks.md).
- Проверки выполняются после регенерации и после фиксации. Создание/удаление объектов, предупреждение Revit, изменение вне объявленных зависимостей или неподтверждённая сохранность откатывают попытку. Сеть целиком не переписывается; связи с непереносимыми соседями должны сохраниться. Предварительный статус не гарантирует успеха на произвольном проекте.
- Для видов проверяются доступные текст, значения, положение и ссылки аннотаций. Форматирование фрагментов текста, некоторые выноски, ссылки на скопированные объекты вида и недоступные свойства остаются ручной проверкой с явным замечанием в журнале. Созданный вид и число скопированных объектов не означают полную проверенность результата. Правила диапазона/подложки и побочных изменений сохраняются до решений D1/D2 в Tasks.
- Удаление сначала проверяется в откатываемой транзакции. Подтверждение показывает количество отмеченных объектов и полный состав удаления с зависимостями. Уровни нельзя удалить, в том числе через зависимости. Зависимые виды и виды с зависимыми видами отклоняются. Для вида разрешено удаление его содержимого и размещений на листах. Изменившийся состав, предупреждения Revit или посторонние изменения откатывают попытку; часть удалений может быть отклонена.
- Уровни и виды из исходного выделения видны в «Элементах», но удалить уровень нельзя, а удаление вида выполняется только на вкладке «Виды».

Автоматических интеграционных тестов и проверенной тестовой RVT-модели нет.
